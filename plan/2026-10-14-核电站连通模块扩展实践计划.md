## 1. 已确认的玩法规则

- A 为一级主结构。B 是唯一直接连接 A 的第一片子结构。
- 后续完整子结构经合法连接口连到 B，才贡献等级；孤立模块不计数。玩家不必按顺序施工。
- 结构等级为 `1 + 与 A 连通的完整子结构数量`；C、D、E、F 是图中实例名称，不是固定等级或独立模板。
- 子结构共用模板，仅位置、水平朝向不同；没有主机，也没有输入／输出仓口或总线。
- 每个连接口规定下一片的相对位置和朝向，玩家自由选择扩展哪些连接口。
- 扩展缺块、方向不符或必要区块未加载，按扩展失败处理并重新计算等级；不主动加载区块。
- 开机时等级发生变化，进行停机。升级和降级都适用；不自动重新开机。
- 相邻模块的实体边界由用户设计。模板接入时仍检查重叠要求是否冲突。
- 本轮的“片”是完整子结构，是计数和检查单位；不是 TST 固定的 16³ 技术分片。

## 2. 连接口是什么

连接口是模板上的几何约定，不是仓口、控制器或新注册方块。它包含：

1. 当前模块上的连接面及连接面中心。
2. 下一片锚点相对当前模块锚点的三维偏移。
3. 下一片相对当前模块的水平朝向。
4. 对接处必须满足的结构规则。

相邻不等于连接。只有端口规定的位置和朝向上的完整模板才计入。所有坐标相对模块自身定义，整体随后随 A 的主控制器朝向转换，不写死世界东南西北。

端口不要求一定开洞：外墙上的对接图案、连接柱、短连接段都能作为几何识别依据。具体使用哪一种，由测试子结构确定。未接下一片的出口不能被规则要求必须存在邻居，否则单独 B 无法有效。

## 3. 测试连接口视图（待用户确认）

以下视图不是最终结构尺寸或方块清单。它给出一种能覆盖用户原图和新增 F 的测试端口布局：前方入口，后方和两侧出口。图上方向均相对当前俯视图，不代表世界固定朝向。

### 3.1 一个模板的俯视图

```text
                  后方出口 P_back
                         o
              +----------+----------+
              |                     |
  侧出口 P_w  o          O          o  侧出口 P_e
              |          v          |
              +----------+----------+
                         i
                     前方入口 P_in

O：模块锚点（坐标参考，不需要放主机）
v：该模板的正面方向
i：连接上游的入口面
o：允许接下一片的出口面
```

每个出口接下一片的前方入口。新模块正面朝向上游。前后串接保持同向，侧向串接产生四分之一圈的相对转向。入口和出口的实体图案必须能够配合，不要求两者用同一个字符或完全相同的装饰。

## 4. 测试子结构的交付内容

第一阶段交付一个完整模板及其两个对接实例，不要求先搭完整核电站。

- 一张俯视图：标明正面箭头、锚点 O、入口 i 和各出口 o。
- 一张入口与出口的近景图或侧视图：标明高度和间距。
- 模板完整方块范围及结构导出文本；说明导出工具的坐标顺序和方向。
- 字符到方块的映射；区分必须空气与不参与检查的位置。
- 一个同向串接实例，以及一个水平转向串接实例。
- 模板有定向方块时，注明轴向／正面要求；标注用方块是否属于最终结构。

先用入口装饰或不对称的结构特征让朝向能被明确识别。测试标记不作为新增方块注册需求。实际对称性及是否需要额外识别特征，在模板交付后核验。

测试阶段不确定最终材料、容量、并行倍率、模块上限或机器 ID。没有子主机注册需求。

## 5. 技术实践步骤

### 阶段一：几何核验

从模板导出规范化局部坐标、锚点和端口表。生成所需水平朝向的形状与端口变换，检查 A→B、B→E、B→C、C→D、C→F 对接关系。

连接计算使用统一坐标转换；不能只旋转字符数组而不变换锚点、端口和定向方块规则。StructureLib 的局部轴包含向下的纵轴语义，不直接套用普通世界 XYZ 的符号。

固定方向预生成形状后沿用 GT `checkPiece()` 的技术路径须以测试模板核验。子结构没有控制器，不能把导出中的控制器占位 `~` 无条件带入每个实例。

完成条件：两类串接坐标准确，整体随 A 旋转后布局正确，错误朝向不被识别为合法扩展。

### 阶段二：连通模块识别

使用队列从固定 B 候选位置开始搜索。每片完整通过后计数并枚举它的端口；失败片不计数，不通过它继续扩展。

每轮临时维护：候选队列、已处理实例、完整模块集合、模块占用位置和必要的检查信息。区分位置及朝向候选；避免某个错误方向的尝试屏蔽同位置的其他合法候选。完整实例的身份和重叠判定在阶段一确定。

- 同一实例从多条路径被发现，仅计数一次。
- 不无限遍历回边或环路。
- 实际存在另一条完整连接路径时，模块仍按连通性计入。
- 不将“强制每片只能有一个父模块”加入玩法规则。
- 模块实体约束发生冲突时，不允许同一空间被多次计数。接缝共享位置按用户明确的接缝规则处理。
- 缺失扩展是正常搜索终点，不把所有空端口变成 A 的成型错误。

搜索上限、超限行为及环路对接几何仍待确认；正式接入前必须有有界搜索和明确的超限处理，不能静默截断后展示成完整等级。

完成条件：B 单片、两种第二片选择、三种第三片选择、孤立片、断链和重复发现均有正确结果。

### 阶段三：等级与运行接入

将结构扩展等级与现有 `fuelRodTier` 分开。保留现有燃料、热量和增殖池状态，不在结构降级时清空它们。容量与并行如何结合两种等级，属于待确认玩法，不能自行赋值。

每轮完整计算后一次性提交等级，不在搜索过程中逐片更新。提交前后等级不同且处于开机状态时，执行停机并给出等级变化原因；用户手动重新开机。

同片数但布局变化，不属于已确认的“等级变化停机”触发条件。首次加载、首次成型与旧 NBT 的初始化不直接视为运行中升级；恢复校验完成前不允许恢复运行。

逐片检查必要区块：未加载片视为失败；后续失去唯一连接路径的片也不计入。调整现有基类的大范围区块检查，避免扩展区块未加载时提前跳过降级检查。A 的必要区块未加载与扩展失败分开处理，不在 A 未被确认时运行。

结构变更触发范围与远端模块变化检测必须一起核验，不能假设原有主机附近的更新传播能覆盖全部扩展。检测刷新周期及性能预算在模块规模确定后确认。

完成条件：运行中加片、拆片、扩展区块卸载均按检测后的新等级停机；重载不丢状态、不误用历史成型结果。

### 阶段四：提示、预览与性能核验

结构识别使用真实世界的端口搜索；建造提示不能只搜索现存完整模块，否则无法提示尚未搭建的下一片。建造提示的目标端口选择及自由布局预览方式待确认。

第一阶段实现完整模块的同步检查，不迁入 TST 的跨 tick 调度。按实际模块数记录扫描成本；需要分次检查时另行设计完整检查快照与运行暂停边界，不能混用不同轮次的半份结果。

## 7. 验收清单

| 场景 | 预期结果 |
| --- | --- |
| 仅 A 完整 | 1 级 |
| A+B | 2 级 |
| A+B+C 或 A+B+E | 3 级 |
| A+B+C+D／E／F | 对应三个子模块完整连通时为 4 级 |
| 先建 C，未建 B | C 不计入 |
| C 缺块，F 只有经 C 的路径 | C、F 不计入 |
| C 必要区块未加载 | 与 C 失败相同；不主动加载 |
| 正在开机，等级上升或下降 | 本轮结果提交后停机，等待手动启动 |
| 未接的合法出口 | 当前模块仍完整 |
| 错误位置或错误朝向 | 不计入 |
| 重复发现、合法回路 | 不重复计数、不无限搜索 |
| 冲突重叠 | 不重复占用计级 |
| A 水平转向 | 各模块位置、端口和朝向整体一致变换 |
| 同片数布局改变 | 不触发仅由等级变化定义的停机 |
| 保存／重载、停机和降级 | 燃料、热量、增殖状态保留；运行前重新确认结构 |
| 远端模块拆除 | 在确认的检测机制与周期内识别，不长期保留虚假等级 |

编译、测试、打包及启动游戏仍需单独授权；格式检查及 Wrapper `spotlessApply` 已获项目许可。独立几何核验仅覆盖坐标算法，不替代游戏内结构、区块事件、停机和存档验收。执行获授权的验证后再更新项目知识库及追加验证记录。

## 8. 实施前待确认

1. 测试模板是否采用第 3 节的入口／三个出口布局，以及各面实际结构、尺寸、锚点和间距。
2. 最大模块数／等级、搜索范围及超限处理；本计划不默认封顶五级，也不默认无限扩展。

4. “开机”判定采用允许工作状态还是仅实际发电／发热状态，待机但开关开启是否纳入。
5. 自由布局的目标端口选择、结构提示及预览方式。
