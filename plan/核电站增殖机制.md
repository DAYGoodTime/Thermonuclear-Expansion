# 核电站增殖机制

> 创建日期: 2026-10-11
> 作者: lin1s（OpenCode 协助）
> 状态: 已实现原型，游戏行为待验收

## 使用方式

核电站支持可选增殖功能。在结构的 B 位置安装增殖输入总线与增殖输出总线，各至少一个；两种总线须成对安装。它们不替代普通燃料输入／输出总线，也不接入普通燃料物品池。

两种增殖总线的物品容量与 ZPM 输入／输出总线一致，均有 64 个物品槽，GUI 为 8×8。外观沿用 LV 输入／输出总线材质；输入总线另保留一个不可使用的父类电路槽，物品过滤、排序及主机遍历均以 64 个物品槽为边界。注册 ID 为 `32103`、`32104`，注册前检查 GT5U 范围及运行时占用，冲突时明确失败、不自动改号。按用户要求，当前没有制造配方，可从创造模式获取。

支持的增殖棒：

| 输入 | 完成后的产物 |
| --- | --- |
| GT 锂燃料棒 | GT 氚燃料棒 |
| GT 萤石燃料棒 | GT 阳光化合物燃料棒（Sunnarium） |
| 本模组增殖燃料棒（钍） | 本模组增殖燃料棒（钍，增殖完成） |
| 本模组稀土增殖燃料棒（17 条元素路线） | 对应路线的增殖完成棒，离心回收目标元素粉 |

输入支持已有部分进度的棒；目标进度读取物品的 `getMaxDamage()`。GT5U `.133` 中两种棒均为 10000 点，GT 产物棒后续提取／离心沿用原有配方。本模组钍棒与稀土棒的用户批准原型目标同为 10000 点，仅用于核电站专用增殖总线，自身不发电、不产热，不作为普通发电燃料棒使用。当前不适配 IC2 原生锂组件或其他模组增殖棒。

钍棒制造与回收原型配方：

| 机器 | 输入 | 输出 | 耗时 / 电压 |
| --- | --- | --- | --- |
| 装罐机 | 1 空燃料棒＋1 钍粉 | 1 增殖燃料棒（钍） | 10 秒 / LV |
| 离心机 | 1 增殖完成钍棒 | 1 铀-233粉＋1 空燃料棒 | 25 秒 / MV |

回收使用 GT5U `.133` 内置 GT++ 的 `MaterialsElements.URANIUM233`，不新增同位素材料。未完成钍棒不能用于该离心配方；制造、离心及增殖展示接入 NEI，增殖展示为假配方，实际由核电站周期推进。物品独立注册在本模组名下，材质直接引用 GT 钍棒／枯竭钍棒资源。以上为原型参数，不是最终平衡。

## 稀土元素增殖棒

新增 17 组独立工作棒／完成棒，共 34 个物品，使用 GT 普通元素粉，只保留起始与结果元素。路线为：

```text
钙 → 钪
锶 → 钇
钡 → 镧 → 铈 → 镨 → 钕 → 钷 → 钐 → 铕 → 钆 → 铽 → 镝 → 钬 → 铒 → 铥 → 镱 → 镥
```

每个箭头是一组独立增殖棒，须分别装罐、增殖与离心回收，不是装入一次便完成整条链。钐棒采用用户确认的「钷→钐」，避免与「钕→钷」使用相同装罐输入，不需要编程电路。

| 步骤 | 输入 | 输出 | 用户批准的原型参数 |
| --- | --- | --- | --- |
| 装罐机 | 1 空燃料棒＋1 起始元素粉 | 1 对应路线的工作增殖棒 | 10 秒 / LV |
| 核电站增殖池 | 工作增殖棒 | 对应路线的完成棒 | 目标 10000 点，每周期全堆脉冲 × 4 |
| 离心机 | 1 对应路线的完成棒 | 1 目标元素粉＋1 空燃料棒 | 25 秒 / MV |

所有原料与产物复用 GT5U `.133` 的 `Materials` 元素材料及 `getDust(1)`；粉末在 load-complete 配方注册时解析，材料缺失时报告具体路线。工作棒以物品 damage 保存进度，已有进度的棒限制单根堆叠；完成棒没有增殖进度，不会再次进入工作池。NEI 展示每条工作棒到完成棒的转换，实际增殖仍由独立池执行。材质复用 GT 钍棒／枯竭钍棒资源，物品名称区分路线与完成状态。

核物理依据见[稀土元素中子捕获与衰变路径](../references/稀土元素中子捕获与衰变路径.md)。钷到钐的补充依据为 `Pm-149 —(n,γ)→ Pm-150 —β⁻→ Sm-150`。游戏不区分同位素丰度、桥接步骤、衰变等待时间、竞争分支或亚稳态，也不模拟钷产物的后续衰变；普通元素粉之间的串联是已确认的游戏简化，不是同位素级闭合生产链。

## 周期与独立物品池

每个主机周期为 20 ticks。普通燃料实际参与本周期燃烧时计算：

```text
P = Σ（实际运行的普通燃料棒数量 × 每根棒的 cell 数）
每根并行增殖棒的进度增量 = P × 4
```

单棒、双棒、四联棒的 cell 数分别为 `1、2、4`。所有并行增殖棒各自获得完整增量，不按增殖棒数量平分，不模拟槽位邻接，不叠加堆芯热量加成。该增量按主机周期计算，不再乘燃料消耗速度或启动倍率；普通燃料的周期消耗必须大于零。

例如，64 根四联燃料棒实际运行时，`P = 256`，每根增殖棒增加 1024 点进度。已有零进度的棒在第 10 个有效周期完成；最后一次多余进度不转移给下一根棒。

主机内部独立增殖池统一上限 512 根，不占用普通燃料并行额度，也不随燃料棒结构等级或电源面板并行设置改变。不同增殖棒、不同已有进度可同时存放；每个有效燃烧周期从专用输入补充空余容量，再推进池内所有工作棒。

待输出产物仍占用池容量，避免输出堵塞时无界装载。完成产物只进入专用输出总线，支持部分输出；剩余部分保留在主机。增殖输出堵塞不阻止普通燃料发电／供热。普通燃料不足、结构等级导致燃料暂停或普通输出堵塞时，不增加增殖进度，但仍能通过输出专用产物的周期回收已完成棒。

停机、结构不完整或邻区块未加载时不推进增殖；卸载、重新加载、模式切换与主机拆卸掉落保留内部工作棒和待输出产物。

## 实现与事务边界

- [独立增殖池](../../../src/main/java/com/lin/thermonuclear/nuclear/BreederPool.java)保存各批棒的数量、物品进度和待输出产物。
- [增殖棒映射](../../../src/main/java/com/lin/thermonuclear/nuclear/GTBreederRod.java)显式映射 GT 锂／萤石棒、本模组钍棒及稀土棒产物；不反射访问 GT 的受保护产物字段。[稀土路线表](../../../src/main/java/com/lin/thermonuclear/nuclear/RareEarthBreedingRoute.java)统一维护物品注册与配方的起终点映射。GT `ItemList.get` 将数量截到 64，内部批次产物须单独保留完整数量。
- [核电站主机](../../../src/main/java/com/lin/thermonuclear/machine/MTENuclearPowerPlant.java)将专用仓口从普通总线列表分离，复用周期事务与 NBT 快照回滚。专用输入只在整个周期交互成功后扣除；输出采用共享 `ItemEjectionHelper` 预留并提交。
- 普通燃料适配接口的 `cells` 提供单根棒的脉冲贡献；默认返回零，GT 适配器读取 `numberOfCells`，其他适配器须明确提供该值才参与增殖。

数量采用独立整数 NBT 字段保存，避免 Minecraft 1.7.10 的物品 `Count` 字节截断大批次。GUI 展示工作棒数量、池容量、全堆脉冲、每根棒的周期进度增量、进度范围及待输出产物数量。
