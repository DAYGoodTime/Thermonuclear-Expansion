# conventions/ 目录规范

`{DOC_ROOT}/conventions/` 用于记录项目开发过程中衍生出的所有规范、用户习惯和备忘事项。

## 定位

这个目录是一个**活文档区**，内容随项目演进持续更新，以最新版本为准。

与 `wiki/` 的区别：
- `wiki/` — 项目知识沉淀（架构、环境、API 等客观事实）
- `conventions/` — 开发约定与偏好（怎么做、用户习惯、注意事项等主观规范）

## 记录内容

| 类型 | 说明 | 示例 |
|------|------|------|
| 开发规范 | 项目开发过程中形成的编码/流程约定 | 命名规范、提交规范、分支策略 |
| 用户习惯 | 用户的开发偏好和工作方式 | 偏好的工具、代码风格、沟通方式 |
| 用户提醒 | 用户明确要求记住的事项 | "以后别用 X 库"、"这个模块不要动" |
| 备忘录 | 需要长期记住的上下文 | 项目特殊约束、历史遗留问题、踩坑记录 |

## 触发条件

以下情况发生时，应更新 conventions/ 下的文档：

- 用户说"记住..."、"以后..."、"别忘了..."、"注意..."
- 用户纠正了你的做法（说明存在偏好差异，应记录）
- 开发过程中形成了新的约定或规范
- 用户明确表达了某种习惯或偏好
- 发现了需要长期注意的坑或约束

## 文件组织

```
conventions/
├── coding-style.md        ← 编码风格与规范
├── git-workflow.md        ← Git 工作流与提交规范
├── user-preferences.md    ← 用户习惯与偏好
├── reminders.md           ← 用户提醒与备忘
└── {其他按需新建}.md
```

文件名使用英文小写 + 连字符，内容用项目对应语言编写。

不强制预创建所有文件，按需新建即可。

## 文档格式

每个 conventions 文档使用简洁格式：

```markdown
# [规范标题]

## [分类 1]

- 规范条目 1
- 规范条目 2

## [分类 N]

- ...
```

conventions 文档不需要元信息头，也不添加「最后更新」等时间字段；修改历史由 Git 管理。

## 更新规则（核心）

1. **以最新为准**：conventions 中的内容如果与之前的记录冲突，直接覆盖旧内容，不保留历史版本
2. **经常更新**：每次发现新的规范/习惯/提醒，立即更新对应文档
3. **就地修改**：不追加修订记录，直接修改原文，不添加或刷新更新时间
4. **合并同类**：同一主题的内容合并到同一文件，不要碎片化
5. **删除过时项**：已经不适用的条目直接删除，不归档

## 与其他目录的关系

- 如果某个 convention 足够重要且稳定，可以升级为 `wiki/` 中的正式文档
- 如果某个 convention 涉及架构级决策，应同时在 `adr/` 中记录
- conventions 中的编码规范可以被 `wiki/编码规范.md` 引用
