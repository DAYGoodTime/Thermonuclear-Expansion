# Wiki 维护规则（强制）

**每次项目代码发生改动后，必须检查并更新 wiki。** 这是 dev-doc-writer 的核心规则之一。

## 触发条件

以下任一情况发生时，必须更新 wiki：

- 新增/删除/重命名模块、文件、目录
- 修改公共接口（函数签名、类定义、API 端点）
- 变更配置项、环境变量
- 引入/移除依赖
- 修改构建、部署、测试流程
- 重构导致架构变化

## Wiki 目录组织（强制）

Wiki 必须按主题分文件夹，面向后续参与开发的人组织内容。推荐结构：

```text
wiki/
├── architecture/       # 架构、模块边界、数据流、技术决策落地说明
├── development/        # 开发环境、编码规范、调试、测试、常见开发流程
├── features/           # 已落地功能的开发者指南、功能内部机制说明
├── operations/         # 构建、打包、发布、部署、回滚、运行维护
├── references/         # 外部资料摘要、平台资料、协议说明、调研沉淀
└── archive/            # 终态、失效、被替换、翻新时移除的 wiki 内容
```

项目已有平铺 wiki 时，后续翻新应逐步迁入主题文件夹；迁移后更新 `{DOC_ROOT}/README.md` Wiki 索引。

## Wiki 内容要求

Wiki 文档必须做到**尽可能详细**，不能只写概要。读者默认是准备参与开发、排障、维护或继续实现功能的开发者。具体要求：

1. **引用完善**：所有提及的模块、文件、函数、类、配置项，必须附带准确的相对路径或代码引用
   - 文件引用格式：`[文件名](相对路径)` 或行内 `` `src/path/to/file.ext` ``
   - 代码引用格式：`` `ClassName.methodName()` `` 并注明所在文件
   - 配置引用格式：`` `CONFIG_KEY` `` 并注明所在配置文件及默认值

2. **结构清晰**：每篇 wiki 必须包含目录级别的章节划分，读者能快速定位

3. **示例充分**：关键概念必须附带代码示例或使用示例，使用项目实际技术栈语言

4. **保持同步**：wiki 中的路径、接口、配置必须与代码实际状态一致。过时的 wiki 比没有 wiki 更有害

5. **禁止编造**：所有引用必须指向真实存在的路径/符号，禁止凭记忆编造路径

6. **开发者指南优先**：尽量写清楚“如何参与开发”，包括入口文件、关键类、扩展步骤、常见命令、测试方法、调试方法、典型坑、排障步骤、注意事项。

7. **项目提示全量沉淀**：与项目任何相关的提示信息、备注、口头约定、历史原因、平台特殊行为、环境差异、临时限制、后续注意点，只要会帮助后续开发，都应写入 wiki。

8. **面向维护**：说明代码为什么这样组织、哪些地方不能随便改、改动后需要同步哪些资源/测试/文档。

## Wiki 更新流程

1. 确认本次改动影响了哪些 wiki 文档（对照上方触发条件）。
2. 如果相关 wiki 不存在 → 在合适主题文件夹下新建。
3. 如果相关 wiki 已存在 → 翻新受影响章节，确保引用路径正确。
4. 翻新时检查旧内容是否仍有效：
   - 明确失效 → 从正文移除，并按 @references/rules.md「归档规则」移入 `wiki/archive/` 对应主题目录。
   - 无法判断是否失效 → 询问用户，不得擅自删除或保留为事实。
   - 仍有效但位置不合适 → 移动到更合适章节或主题文件夹，并更新链接。
5. 更新 `{DOC_ROOT}/README.md` 的 Wiki 索引。
6. 不添加或刷新「最后更新」等时间字段；维护对应文档时移除已有字段，修改时间通过 Git 历史查询。
7. 追加修订记录，说明新增、翻新、移除和归档内容。

## 翻新与失效内容处理（强制）

翻新 wiki 时必须主动清理过期内容。过期内容包括：

- 路径、文件名、类名、函数名、配置项已经不存在
- 架构描述与当前代码不一致
- 命令、打包流程、测试流程已经不适用
- 已被新方案替代的临时 workaround
- 已完成且不再需要作为活跃指南的迁移说明
- 与当前项目方向冲突的历史建议

处理规则：

1. 能确认失效：从正文移除，并归档原文。
2. 不能确认：向用户说明疑点并询问。
3. 移除内容不得直接丢弃，必须写入 `wiki/archive/<主题>/`。
4. 如果整篇 wiki 失效，将整篇移动到 `wiki/archive/<主题>/`。
5. 如果仅部分段落失效，创建“移除内容归档”文件，记录来源、原章节、移除原因和原文。

## 推荐的 Wiki 文档清单

根据项目实际情况，按需创建以下 wiki（不强制全部创建，按项目需要逐步补充）：

| 文档 | 内容 | 何时创建 |
|------|------|----------|
| `architecture/项目架构概览.md` | 技术栈、分层架构、目录结构、核心数据流、模块依赖关系 | 项目初始化时 |
| `architecture/模块边界.md` | 各模块职责、禁止跨层调用、扩展点 | 模块较多时 |
| `development/开发环境搭建指南.md` | 环境要求、安装步骤、启动命令、常见问题 | 项目初始化时 |
| `development/编码规范.md` | 命名约定、导入规则、类型使用、组件规范 | 团队协作时 |
| `development/测试指南.md` | 测试框架、运行命令、覆盖率要求、测试数据 | 有测试时 |
| `development/调试指南.md` | 日志、断点、常见故障定位、排障步骤 | 问题积累后 |
| `features/功能开发指南.md` | 已落地功能的入口、数据流、扩展方式、注意事项 | 功能稳定后 |
| `references/API文档.md` | 端点列表、请求/响应格式、认证方式、错误码 | 有 API 时 |
| `references/数据模型.md` | 数据库表结构、实体关系、字段说明 | 有数据层时 |
| `operations/部署指南.md` | 构建命令、部署流程、环境配置、回滚步骤 | 需要部署时 |
| `operations/版本发布流程.md` | 版本号、打包、发布、回滚、验收清单 | 有发布流程时 |
| `development/FAQ.md` | 开发中的常见问题与解答 | 问题积累后 |
