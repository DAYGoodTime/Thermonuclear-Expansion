# 燃料棒方块

> 创建日期: 2026-10-07
> 作者: OpenCode
> 状态: 四级基础方块、材质、核电结构、制造配方及分级热容量／最大并行已实现，游戏行为待验收

## 已确认要求

共 **4 个等级**，用于核电站结构，决定**可存储热量的上限及最大并行**。当前名称为一级至四级燃料棒方块，不自动对应 GT 电压等级。

## 当前实现

| 等级 | 注册名 | Java 引用 | PNG 后缀 |
| --- | --- | --- | --- |
| 一级 | `thermonuclear:fuel_rod_tier_1` | `BlockLoader.fuelRod(1)` | `_1` |
| 二级 | `thermonuclear:fuel_rod_tier_2` | `BlockLoader.fuelRod(2)` | `_2` |
| 三级 | `thermonuclear:fuel_rod_tier_3` | `BlockLoader.fuelRod(3)` | `_3` |
| 四级 | `thermonuclear:fuel_rod_tier_4` | `BlockLoader.fuelRod(4)` | `_4` |

每级为独立方块，默认物品元数据 0，`BlockFuelRod` 定义四级燃料棒，`BlockTieredMachineComponent` 统一注册等级。运行资源为 `assets/thermonuclear/textures/blocks/fuel_rod/fuel_rod_{side,top,bottom}_{等级}.png`；完整立方体，无自发光或 TileEntity。轴向能力由 `BlockMachineComponent` 提供，按放置面法线选择 Y／X／Z 轴，世界元数据分别为 0／4／8；端面正方向使用 top，负方向使用 bottom，其余面共用 side。原木渲染类型 31 同时旋转侧面 UV；基础采集属性与[低压轴](低压涡轮轴.md#当前实现)相同。

作为反应堆构建时，所有位置必须同级，且必须竖直放置（Y 轴，元数据 0）；横放（元数据 4/8）按不匹配拒绝。`MTENuclearPowerPlant.getFuelRodTier()` 由结构重检推导等级，`fuel_rod` 建造通道选择 1—4 级，默认一级，全息与自动建造同样按 Y 轴提示。

各级通过 `BlockTieredMachineComponent → BlockWrenchComponent` 使用 GT 外壳的 `wrench` 采集类型，并由 GT 扳手通过 Forge 旋转接口右键设置轴向；工具耐久、音效与选面规则沿用 GT，不另写右键处理器。放置、拆除和旋转触发 GT 原生结构更新；禁用精准采集，掉落物不保留轴向元数据。旋转为横向后不再满足反应堆结构要求，游戏行为待验收。

不显示选面网格；右键分区规则与[低压轴](低压涡轮轴.md#当前实现)相同。燃料棒仅区分 Y／X／Z 轴，相反方向不改变轴向。

这些方块仅作为多方搭建方块，不是燃料棒物品，也没有任何特殊效果。主机根据结构等级确定热缓存上限与最大并行，不改变单根燃料寿命、效率或反射公式。一级至四级的基础放置属性相同。

## 热容量与最大并行(最初设计)

| 燃料棒方块等级 | 最大热量 | 最大并行 |
| --- | --- | --- |
| 一级 | 50000 | 8 |
| 二级 | 100000 | 32 |
| 三级 | 1000000 | 128 |
| 四级 | 2147483647（`Integer.MAX_VALUE`） | 512 |

数值统一定义在 `BlockFuelRod.heatCapacity(tier)`／`maxParallel(tier)`，`MTENuclearPowerPlant.getHeatCapacity()`／`getMaxParallel()` 按结构等级查询，无有效等级时均为 0。并行按同批燃料棒物品数量计算，`getMaxParallelRecipes()` 将等级上限接入 GT 电源面板；手动设置范围分别为 1—8／32／128／512，启用“始终使用最大并行”时跟随等级上限。新批次装载上限由 `getFuelRodLimit()` 取等级上限与 `getTrueParallel()` 的较小值；

降级后已有燃料和热量不截断；超出燃料棒方块等级最大并行的燃料暂停处理，供热／停机冷却仍可排热。仅降低电源面板并行设置时，已有批次继续处理，新上限从下一批装载生效。NBT 与事务回滚只按非负有限值及 int 最大值校验热量，不依赖加载时尚未恢复的结构等级。冷却后已有热量加计划产热超过当前等级容量时仍紧急关机，恰好等于容量允许。
