## 来源与保留方式

用户另指定了本地代码参考项目 `D:\DEV\mcmod\GT-Not-Leisure`。编写或修改功能前按 [GTNL 参考索引](GT-Not-Leisure参考索引.md) 检索并阅读相关实现；它与下述 MessTech 迁入 Markdown 的来源不同，不能混为同一项目。

仓库已有的 [knowledge.md](../../knowledge.md) 和 [GT5U-NOTES.md](../../GT5U-NOTES.md) 内容来自 MessTech。保留原文和原路径用于历史追溯；本项目现状以[项目知识库](../development/项目知识库.md)及本仓库源码为准。

来源资料中的 `com.MessTech`、`MTMultiMachineBase`、各个 `MT*` 机器、32400 等机器 ID、`tools/` 验证脚本、`tmp/` 源码树和翻译库均不在本仓库。`repo-readme.md`、`tmp/Compare.md` 等原项目交叉引用也不是本项目入口。不得按这些路径编造已有文件、直接继承不存在的类或复用注册 ID。

## API 与数值核验流程

1. 从本项目 `dependencies.gradle` 获取整合包清单版本，通过 Gradle 解析出具体 GT5U、GTNHLib、StructureLib 等版本。
2. 在解析到的开发 JAR、对应版本源码和 RFG 生成源码中确认包名、签名与实际行为。`build/rfg/` 只在相应准备任务完成后出现。
3. 核对跨模组注册时机、服务端/客户端边界、库存消耗与输出堵塞行为，再编写本项目代码。
4. 记录核验版本、源码位置和验证结果；未经复核的来源数值不进入本项目的已确认平衡表。

来源文档记录了多个时期的基线，例如 GT5U `5.09.54.133` 快照和由 `2.9.0-RC-1` 清单解析的依赖。它们不能替代当前构建中的 `2.9.0-beta-3` 清单。原项目的 harness 成功、游戏现象和 pending 列表同样不代表本项目验证结果。

## 转化为本项目知识的规则

通用经验只有经过当前依赖核验或本项目测试后，才作为事实写入 `wiki/`。机器实现与产品范围以本项目代码和用户确认结果为准；来源项目的无线电网、模块系统、太空机器和其他功能不自动成为本模组需求。
