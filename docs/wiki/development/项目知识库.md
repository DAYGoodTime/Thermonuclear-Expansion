# Thermonuclear Expansion 项目知识库

## 项目定位与当前实现

面向 GTNH 的热核与蒸汽能源扩展附属模组，扩展 `IC2 热冷却液 → 热交换 → 蒸汽 → 涡轮 → 电力` 链路，不建立温度或温差模型。[规划原稿](../../../plan/GTNH-Thermonuclear-Expansion-Plan.md)描述目标，`src/` 与构建配置描述实现，两者分开使用。

当前机器能力：

| 机器 | 当前能力 |
| --- | --- |
| 核电站 | 消耗燃料直接发电或供热，直接发电支持芯片升级后的无线输出；支持分级热量缓存、并行设置、持续超限后的堆芯融毁与冷却排热；供热可加热钾钠合金复合冷却液，专用增殖总线支持 GT 锂棒／萤石棒及本模组稀土元素棒转换，完成棒经后续配方回收目标材料。 |
| 热交换站 | 根据输入热液自动选择唯一路径：IC2 热冷却液生产过热蒸汽，热超级冷却液生产超临界蒸汽，热钾钠合金复合冷却液生产超超临界蒸汽；消耗蒸馏水并返还冷却液，无蒸汽模式切换。 |
| 大型蒸汽涡轮机 | 消耗不同类型的蒸汽发电并回收蒸馏水，无需 GT 转子，支持设置耗汽上限及芯片升级后的无线输出；低压轴支持前三种蒸汽，高压轴额外支持超超临界蒸汽。 |
| 调试结构构建机 | 调试专用：只通过全息提示／蓝图自动搭建装载的草稿结构，骨架匹配即成型，不处理配方、不接受仓口；当前装载 `dev/nuc-child.txt` 草稿。 |

增殖为可选功能，专用输入／输出总线成对安装，不占普通燃料物品池或并行额度；机制说明快照见[核电站增殖机制](../../../plan/核电站增殖机制.md)；当前配方见[文档索引](../../README.md)。

核电站使用主结构背面、右侧双入口的贴墙模块扩展：主子结构保留独立模板与完整外墙，统一主机水平朝向，子模块通过四个水平相邻方向的 BFS 连通搜索识别。管道等级继续决定模块总数上限；模块管道与燃料棒分别只读匹配主结构对应等级，不接受混级或借失败模块继续连接。完整模块才计数，达到上限立即停止；NEI `extra` 提供仅主结构、背面一片、背面连续两片三级示例，主子结构共用 `pipe`／`fuel_rod` 通道；世界全息与自动搭建采用同一示例选择，不限制实际自由连接。几何、模板与验收边界见[核电站模块结构](核电站模块结构.md)

核电站成型并关机后，可用 GUI 弹出按钮将内部工作燃料棒送至普通输出总线；输出不足时保留剩余棒及其进度，输出全堵时不改动物料。弹出棒的不足一个周期的已用寿命向上取整，寿命耗尽则输出乏燃料；不弹出增殖棒，不改变原有待输出产物流程。

**新增方块系列**

- 低压／高压涡轮轴方块，用于涡轮结构，支持按放置方向调整轴向；等级限制蒸汽准入，超超临界蒸汽仅允许高压轴使用。
- 燃料棒方块，用于核电站结构等级决定核电热容量和最大并行。
- 新增涡轮扇叶方块：引用钢块材质，用于涡轮结构。
- 新增安全壳机械方块：沿用 GT 强化混凝土材质，用于核电站主结构外壳、可替换仓口位置及扩展模块壳体。

**新增流体系列**

- 超超临界蒸汽；作为热交换机高级输出蒸汽，接入高压轴涡轮发电。
- 冷／热钾钠合金复合冷却液: 只能通过工业搅拌机制造，作用于热交换机和反应堆热模式的冷却液。

方块与流体初期设计分别位于 `wiki/blocks/` 和 `wiki/fluids/`；具体实现、配置默认值与范围以源码及字段旁注释为准。

**新增物品系列**

- 无线升级芯片: 右键本模组电力机器解锁 ”无线电网“模式，机器拆除后仍保留，当前未添加制造配方。在”无线电网“模式下，机器不需要安装动力仓\能源仓，能量输入输出直接从主机所有者所属的 GT 无线电网／团队中进行交互。如果安装了能源仓室，则继续按原来逻辑执行，不进入无线模式。

## 目录结构

```text
src/main/
├── java/com/lin/thermonuclear/  # 模组生命周期与配置
│   ├── api/                   # 燃料、冷却液与换热规则接口及注册表
│   ├── loader/                # 内容注册与加载
│   ├── block/                 # 方块基类、分级组件及配套 ItemBlock
│   ├── item/                  # 物品基类、增殖棒公共机制与路线变体
│   ├── machine/               # 机器逻辑、结构与专用仓口
│   ├── nuclear/               # 核燃料与冷却处理
│   ├── recipe/                # 换热、发电计算与展示配方
│   ├── registry/              # 统一物品引用、流体登记、冷却液及蒸汽类型定义
│   ├── gui/                   # 机器界面
│   ├── nei/                   # NEI 集成
│   ├── asm/                   # CorePlugin 入口
│   └── mixins/                # Mixin 加载入口
└── resources/                 # 加载配置、本地化与材质
dev/                           # 结构导出与材质开发工具
docs/                          # 开发知识与专题资料
plan/                          # 产品规划与任务
```

目录说明只覆盖主要职责，不维护逐文件清单；局部实现细节不写入知识库，仅在关键代码处注释。

方块与物品的公共基类负责 Forge 注册，分类类定义等级／变体，Loader 组织加载；`TNCItemList` 统一列举机器、仓口、方块物品与普通物品，由各 Loader 绑定；`get(amount)` 返回保留元数据及 NBT 的独立副本，拒绝未绑定读取、重复绑定及无效物品，init 结束前检查全部条目已绑定。配方和 NEI 通过枚举取物品，结构判定仍使用有类型的方块入口及等级集合；枚举不执行注册、不分配机器 ID。轴向能力合入方块基类，分级组件由父类统一注册；各等级仍使用原注册名，方块元数据只存轴向，增殖棒 damage 只存进度，不合并为元数据物品。

方块分类类在构造器中用 `addInfo(语言键, 参数...)` 按顺序声明提示，语言键不绑定注册名；同类各等级共用说明只声明共享键，等级专属说明单独追加，多行逐键调用。`ItemBlock` 传递完整悬停上下文，基类在悬停时翻译并格式化；燃料棒分类类统一提供等级参数，核电站与 Tooltip 共用，不在语言文件维护数值。

## 验证与知识维护

- 扩展整轮结果提交后，开关开启或仍有预付周期时等级变化走原生停机，等待手动重启；保存等级仅用于比较，恢复前必须重验。扩展搜索随 GT 原生结构检查触发，不固定轮询、不随配方周期扫描；远端变动未触发原生通知时使用 GUI 手动检查。主结构缺区块暂停、恢复后复验，扩展缺区块在结构检查时按断连降级，不主动加载区块。扫描采用单调时钟超时，失败不提交部分等级。独立几何模型不证明游戏停机、存档或性能正确。
- 扩展组织参考 GTNL `PCBFactory` 的独立片段与多次 `buildPiece()`，不复用其固定布局或自有 API；按当前 GT5U ／StructureLib  核对 API。模块模板与几何合入 `NuclearModuleStructure`，真实匹配通过 `iterate()` 复用建造／预览的结构元素；先确定主等级，保留整盒区块预检、逐元素超时与显式失败记录，不使用会更新主结构统计的 `checkPiece()`。BR6343 通道枚举用于发现 `extra`，不新增编译依赖。
- 投影仪的通道补全与说明只来自 StructureLib 全局注册表 `ChannelDescription`，不扫描机器结构：在 `CommonProxy.init` 中晚于方块注册调用 `StructureLibAPI.registerChannelDescription(通道, modid, 语言键)` 才出现在补全列表并带有说明 tooltip；再按等级调用 `registerChannelItem(通道, modid, 值, 物品栈)` 登记指示物，才支持从 NEI 拖入与中键拾取填入，该调用同时为物品追加指示物提示。语言键按 `channels.<modid>.<通道>` 写入 `lang`；通道名必须全小写，配置界面的输入框会强制转小写。未注册的通道仍可手动填写生效，BR6343 的 NEI 滑条不读此表。
- 公共基类通过 `FluidStack.isFluidEqual` 匹配输入及去重 ME 同种库存，遵循流体与 NBT 比较语义；指定仓口的统计与扣除共用 ME／多流体仓口遍历并保留原始事务栈。参考 GTNL `SteamMultiMachineBase#getStoredFluids()`，API 按当前 GT5U `.205` 核对，不采用参考库的新增接口；真实 AE 网络行为待游戏验收。
- 联机流体 ID 以服务器为准；换热与涡轮 NEI 预览通过 GT 显示 getter 隐藏不可用流体槽，保留槽位及实际配方，不使用 Mixin。服务器缺少本模组时预览可能不完整；共享工业搅拌机制造配方不在此防护范围。
- 仅收录影响后续开发的关键知识和关键错误修正，用简短结论表述，不展开具体实现、排查过程或逐次变更。
- 普通改动、局部细节与临时提示不入库；仅在关键代码处保留必要注释。
- 事实、规划与验证结果分开记录；Java 编译与隔离逻辑检查不替代完整构建或游戏验收，历史验证不代表当前工作区已验收。
- 文档修订写入[文档修订记录](../../文档修订记录.md)，命令与结果写入[开发验证记录](../../开发验证记录.md)；历史记录与归档仅按需追溯，统一规则见 [AGENTS.md](../../../AGENTS.md#文档维护与历史读取)。
