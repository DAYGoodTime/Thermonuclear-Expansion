# Thermonuclear Expansion 项目知识库

> 最后更新: 2026-10-09

## 项目定位与当前实现

面向 GTNH 的热核与蒸汽能源扩展附属模组，规划从 EV 阶段扩展 `IC2 热冷却液 → 热交换 → 蒸汽 → 涡轮 → 电力` 链路，不建立温度数值或温差模型。[规划原稿](../../../GTNH-Thermonuclear-Expansion-Plan.md)描述目标，`src/` 与构建配置描述实现，两者分开使用。

三台原型已有独立结构、GUI、NBT 和双语资源，共享 20 tick 处理周期与 GT 送电链：

| 机器 / 批准 ID | 当前能力 |
| --- | --- |
| 核电站 / `32100` | 直接发电或供热；可存档的热缓存，计划产热超限关机；停机优先流体排热，无有效流体冷却时自然散热；四级同级燃料棒方块决定热容量 50000／100000／1000000／2147483647 及最大并行 8／32／128／512，电源面板设置控制新批次装载数量，管道不分级 |
| 热交换站 / `32101` | 每 20 tick 按库存与两侧出口容量换热，最小 1 L 热冷却液；IC2 热冷却液仅产普通／过热蒸汽，固定 40／20 L/L，热超级冷却液仅产超临界蒸汽，保留 5 倍系数为 50 L/L；统一 160 L/蒸馏水 L，以预付额度跨批结算水耗；等量返还冷却液，NEI 展示三条 1000 L 热流体预览，结构 `9×14×7` |
| 大型蒸汽涡轮机 / `32102` | 无需 GT 转子，处理四级蒸汽，基础能量为 1.5／4.5／7.5／10.5 EU/L，仅乘启动倍率；回收蒸馏水，参数窗口设置 long 型 20 tick 耗汽上限，NEI 展示四条比例配方；结构 `30×15×15`，26 个同级轴支持低压／高压两级升级，轴等级不改变性能 |

机器 ID 从 `32100` 递增已获用户批准，注册时检查范围与占用，冲突即失败，不覆盖或自动改号。已有[超超临界蒸汽](../fluids/超超临界蒸汽.md)的独立流体注册、双语名称与客户端 NEI 列表入口；两种现有热冷却液均禁止生产该流体，尚无其他生产路径，但涡轮已支持消耗该流体发电。当前机器仅为创造模式测试内容；没有制造配方、主控电路板、温度／布局机制、维护故障或终局机器。

另有六种独立可放置组件方块：低压／高压涡轮轴、一级至四级燃料棒方块。均注册到 `thermonuclear` 命名空间，在创造模式建筑方块页提供，采用用户交付的 16×16 顶／底／侧面材质；一级至四级燃料棒已有 LV 组装机配方，均为 10 秒、30 EU/t、输出 1 个，材料见[燃料棒方块](../blocks/燃料棒方块.md#制造配方)，其余组件无配方；均无 TileEntity。六种方块均按放置面选择 Y／X／Z 轴（元数据 0／4／8），端面与原木渲染的侧面 UV 随方向变化，掉落及取块恢复物品元数据 0。涡轮 26 个同级轴须沿机身长轴，常规结构为横向，建造／预览随主机朝向推导；旧竖直轴须手动重新放置。轴等级不改变性能，涡轮无需控制器内 GT 转子；燃料棒接入核电 52 个同级 D 位置，允许三轴混用，默认建造仍为 Y 轴，等级决定热容量和最大并行，不改变单根燃料公式。注册名与面映射详见[低压轴](../blocks/低压涡轮轴.md)、[高压轴](../blocks/高压涡轮轴.md)及[燃料棒方块](../blocks/燃料棒方块.md)。

结构、燃料公式、运行事务、预览兼容与配置详见[原型开发指南](第一阶段原型开发指南.md)。燃料热值不等于 IC2 原版散热缓存或 GUI 热输出，区分依据见[IC2 燃料棒公式](../references/IC2-2.2.828反应堆燃料棒公式.md)。

## 验证与知识维护

燃料棒方块分级性能入口为 `MTENuclearPowerPlant.getHeatCapacity()`／`getMaxParallel()`／`getFuelRodLimit()`，一级至四级分别为热量 50000／100000／1000000／2147483647、并行 8／32／128／512。`getMaxParallelRecipes()` 将等级上限接入 GT5U `.133` 的电源面板动态同步，未知等级时仅为输入框返回 1，实际装载上限仍为 0；新批次取等级上限与 `getTrueParallel()` 的较小值。启用始终最大时锁定上限，关闭后可手动输入。GUI 在状态、模式后同步显示燃料棒等级、最大并行及当前单批上限，另显示实际批量及热容量。管道等级与容量限制已取消，六种管道外壳可混用；旧 `nuclearHeatCapacity`／`nuclearFuelRodsPerPipeTier` 仅保留配置兼容，不再读取。结构降级后的热量和燃料完整保留，热量加载／事务回滚按 0—int 最大值校验，超过等级上限的批次暂停，冷却仍可进行；仅降低面板并行从下一批装载生效。此次指定 GTNL GUI 参考路径不可访问，已核对本地 GT5U `.133` 的 `MTEMultiBlockBaseGui.makeParallelConfigurator()` 与 `MTEMultiBlockBase.getTrueParallel()`，未新增依赖；完整模组编译、游戏内升降级、面板交互、重载和同步未验收。

涡轮展示配方只调用 GT5U `.133` 实际提供的 builder API，不使用不存在的 `noOptimize()`；`GTRecipeBuilder.build()` 的专用构造路径直接保存流体输入量，1000 L 无需额外禁用优化。用户发现的该处编译错误已从源码修正；历史格式及源码字符串检查并未覆盖方法存在性，不能当作编译通过。

涡轮耗汽不读取 GT 转子最佳流量或 `rotorCapacityMultiplier`，也不反算动力仓额定对应耗汽量；理论及实际产电允许高于动力仓额定，公共 `generate()` 仍只向 GT 请求额定／int 安全范围内的电力，剩余直接作废。GTNL `common/machine/multiblock/SiphonTurbine.java` 的吸汽／推电分离仅作参考，不采用其 EU 缓存和直接储能注入。运行速率统一为 L/t 和 EU/t，批次升数明确命名 `LitresPerCycle`，共享预付功率字段为 `operatingEUt`；GUI 的 L/20 tick 参数与旧 NBT 单位保持不变。独立探针覆盖批次转速率、不同周期长度的能量守恒、启动线性公式、超过旧 200 亿升界限及产电不按额定钳位；完整模组编译、真实 GT 周期、电力作废、仓室与 NBT 行为待验证，单位约定见[原型指南](第一阶段原型开发指南.md#涡轮时间单位约定)。
