# Thermonuclear Expansion 项目知识库

> 最后更新: 2026-10-07 15:06

## 项目定位与当前实现

面向 GTNH 的热核与蒸汽能源扩展附属模组，规划从 EV 阶段扩展 `IC2 热冷却液 → 热交换 → 蒸汽 → 涡轮 → 电力` 链路，不建立温度数值或温差模型。[规划原稿](../../../GTNH-Thermonuclear-Expansion-Plan.md)描述目标，`src/` 与构建配置描述实现，两者分开使用。

三台原型已有独立结构、GUI、NBT 和双语资源，共享 20 tick 处理周期与 GT 送电链：

| 机器 / 批准 ID | 当前能力 |
| --- | --- |
| 核电站 / `32100` | 直接发电或供热；供热存入可配置、可存档的热缓存，计划产热超限关机；停机优先流体排热，无有效流体冷却时自然散热；8 级同级管道控制燃料批量 |
| 热交换站 / `32101` | 每 20 tick 按热冷却液、蒸馏水库存尽量换热，由冷却液／蒸汽两侧出口剩余容量限流；返还冷却液，选择普通、过热、超临界或超超临界蒸汽；当前结构 `9×14×7` |
| 大型蒸汽涡轮机 / `32102` | 使用 GT 转子消耗普通蒸汽发电并回收蒸馏水；当前结构 `3×3×3` |

机器 ID 从 `32100` 递增已获用户批准，注册时检查范围与占用，冲突即失败，不覆盖或自动改号。已有[超超临界蒸汽](../fluids/超超临界蒸汽.md)的流体注册、双语名称与热交换站产出，尚无对应发电设备。当前机器仅为创造模式测试内容；没有制造配方、主控电路板、温度／布局机制、维护故障、终局机器或最终平衡。

另有六种独立可放置组件方块：低压／高压涡轮轴、一级至四级燃料棒方块。均注册到 `thermonuclear` 命名空间，在创造模式建筑方块页提供，采用用户交付的 16×16 顶／底／侧面材质；无配方、TileEntity 或机器结构／性能接入。燃料棒方块尚不提高核电热容量，涡轮轴不替代控制器内 GT 转子。注册名与面映射详见[低压轴](../blocks/低压涡轮轴.md)、[高压轴](../blocks/高压涡轮轴.md)及[燃料棒方块](../blocks/燃料棒方块.md)。

结构、燃料公式、运行事务、预览兼容与配置详见[原型开发指南](第一阶段原型开发指南.md)。燃料热值不等于 IC2 原版散热缓存或 GUI 热输出，区分依据见[IC2 燃料棒公式](../references/IC2-2.2.828反应堆燃料棒公式.md)。

## 验证与知识维护

核电供热在开机且结构有效时先计算已有热量的冷却，独立于燃料可用性和启动倍率；开机直发模式不冷却。只转换已有热量足够加热的整数升冷却液，未转换热量留在缓存；出口不足时缩减冷却批量。冷却后的热量加本周期计划产热超过上限时直接关闭工作开关，不再按容量缩减燃料消费；恰好等于上限允许。超限产热周期取消冷却输入、产物及燃料消费，内部状态恢复快照，手动开机后才重试。停机时由 `processIdleCycle()` 独立事务每 20 tick 尝试现有流体配方冷却，不消耗燃料、不重启生产；本周期未能完成流体冷却则按用户选定的默认 100 热量/秒自然散热，可配置 `nuclearPassiveCoolingPerSecond`，最低为零。停机冷却要求有效结构、检查完成及邻近区块加载，不补算离线散热，不依赖当前模式或启动倍率；流体冷却成功时不叠加自然散热。停机及事务调用已核对缓存 GT5U `.133` 源码；本次 GTNL 参考目录不可访问，未完成参考对照。蒸馏水产汽余量使用 `tnDistilledSteamRemainder` 保存，旧存档缺失为零，不把旧的未参与运算的冷却液／水余量键迁移为蒸汽。满负荷流体速率按转换比例显示，实际蒸汽速率使用本批输出量。公式和事务边界见[原型开发指南](第一阶段原型开发指南.md#燃料适配与核电模式)，实际游戏及特殊仓室行为仍需验收。

用户已允许全部格式检查及配套的自动格式化，可通过 Wrapper 运行 `spotlessApply`、`spotlessCheck` 及各语言格式检查；编译、测试、资源处理、打包和其他 Gradle 任务仍需另行明确许可。独立验证仅记录自身覆盖范围，未执行的构建及游戏检查保持未验证。

热交换站出口限流使用缓存 GT5U `.133` 的 `FluidEjectionHelper` 独立事务模拟，再按最大可容纳批量重新预留并提交；参考仓库本次不可访问，未完成 GTNL 对照。旧 `exchangeHotFluidPerCycle`、`exchangeCycleTicks` 和 `tnExchangeThroughputRemainder` 已退出运行逻辑。真实仓室、ME 网络、游戏内守恒与显示仍需验收。

组件方块已通过独立局部 `javac` 缓存 API 编译与 PNG／语言映射检查，不代表完整构建、Forge 游戏注册、库存／世界渲染、挖掘掉落或服务器兼容验收。参考 GTNL 的 `loader/BlockLoader.java`、`loader/MaterialLoader.java` 与 `common/block/casings/column/MetaBlockColumn.java`／`ItemBlockColumn.java` 的注册和分面图标思路；本项目实现仅使用本地 Minecraft 1.7.10／Forge 源码缓存核对过的 API，没有复制其代码、资源、ID 或高抗爆属性，也没有新增依赖。
