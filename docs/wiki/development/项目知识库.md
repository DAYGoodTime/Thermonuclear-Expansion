# Thermonuclear Expansion 项目知识库

## 项目定位与当前实现

面向 GTNH 的热核与蒸汽能源扩展附属模组，扩展 `IC2 热冷却液 → 热交换 → 蒸汽 → 涡轮 → 电力` 链路，不建立温度或温差模型。[规划原稿](../../../plan/GTNH-Thermonuclear-Expansion-Plan.md)描述目标，`src/` 与构建配置描述实现，两者分开使用。

当前机器能力：

| 机器 | 当前能力 |
| --- | --- |
| 核电站 | 消耗燃料直接发电或供热，直接发电支持芯片升级后的无线输出；支持分级热量缓存、并行设置、持续超限后的堆芯融毁与冷却排热；供热可加热钾钠合金复合冷却液，专用增殖总线支持 GT 锂棒／萤石棒及本模组稀土元素棒转换，完成棒经后续配方回收目标材料。 |
| 热交换站 | 根据输入热液自动选择唯一路径：IC2 热冷却液生产过热蒸汽，热超级冷却液生产超临界蒸汽，热钾钠合金复合冷却液生产超超临界蒸汽；消耗蒸馏水并返还冷却液，无蒸汽模式切换。 |
| 大型蒸汽涡轮机 | 消耗不同类型的蒸汽发电并回收蒸馏水，无需 GT 转子，支持设置耗汽上限及芯片升级后的无线输出；低压轴支持前三种蒸汽，高压轴额外支持超超临界蒸汽。 |
| 调试结构构建机 | 调试专用：只通过全息提示／蓝图自动搭建装载的草稿结构，骨架匹配即成型，不处理配方、不接受仓口；当前装载 `dev/nuc-child.txt` 草稿，注册 ID 32105。 |

核电站、热交换站和大型蒸汽涡轮机主机均已有 LV 组装机制造配方。布局模拟与维护故障尚未实现。主控电路板系统、二级纯净水核电路线及独立超超临界蒸汽涡轮机已取消，不再列入待实现机制；不建立温度系统。

增殖为可选功能，专用输入／输出总线成对安装，不占普通燃料物品池或并行额度；总线已有组装机制造配方，并可在合成台通过螺丝刀双向转换。钍棒增殖路线已取消，不列入待实现功能。增殖池保留进度与堵塞产物，机制说明快照见[核电站增殖机制](../../../plan/核电站增殖机制.md)，其中钍棒路线及尚未添加总线配方的描述已失效；当前配方见[文档索引](../../README.md)。

核电站使用主结构背面、右侧双入口的贴墙模块扩展：主子结构保留独立模板与完整外墙，统一主机水平朝向，子模块通过四个水平相邻方向的 BFS 连通搜索识别，不使用外接连接管道。管道等级继续决定模块总数上限；模块管道与燃料棒分别只读匹配主结构对应等级，不接受混级或借失败模块继续连接。完整模块才计数，达到上限立即停止；扩展等级不改变热容量、并行或能量公式。NEI `extra` 提供仅主结构、背面一片、背面连续两片三级示例，主子结构共用 `pipe`／`fuel_rod` 通道；世界全息与自动搭建采用同一示例选择，不限制实际自由连接。几何、模板与验收边界见[核电站模块结构](核电站模块结构.md)，尚未完成整模组编译或游戏验收。

核电站成型并关机后，可用 GUI 弹出按钮将内部工作燃料棒送至普通输出总线；输出不足时保留剩余棒及其进度，输出全堵时不改动物料。弹出棒的不足一个周期的已用寿命向上取整，寿命耗尽则输出乏燃料；不弹出增殖棒，不改变原有待输出产物流程。按钮同步参考 GTNL `common/gui/modularui/AssemblerMatrixGui.java`，物料移动参考 `common/machine/multiblock/NuclearReactor.java` 的保留堵塞物料思路；本项目按 GT5U `.133` 的 `ItemEjectionHelper` 核验事务与部分输出 API，不采用参考库 `.183` 的专用棒总线实现。游戏行为待验收。

- 新增方块：低压／高压涡轮轴与不同等级的燃料棒方块，分别用于涡轮和核电站结构，支持按放置方向调整轴向；燃料棒方块已有组装机配方，等级决定核电热容量和最大并行。
- 低压／高压涡轮轴已有组装机配方；等级限制蒸汽准入，超超临界蒸汽仅允许高压轴使用。配方材料按缓存 GT5U API 核验，低压轴使用用户确认的钢齿轮箱。
- 新增涡轮扇叶方块：独立可放置组件，引用钢块材质，已有 LV 组装机配方；已接入涡轮结构判定，替代旧钢块扇叶。
- 新增安全壳机械方块：独立可放置机械组件，沿用 GT 强化混凝土材质，用于核电站主结构外壳、可替换仓口位置及扩展模块壳体；这些位置不再接受 GT 强化混凝土。化学浸洗槽配方在钢框架基础上增加致密铅板，配方注册及游戏内选择、结构判定行为待验收。
- 新增流体：超超临界蒸汽及冷／热钾钠合金复合冷却液；复合冷却液通过工业搅拌机制造、核电站加热和热交换产汽，接入高压轴涡轮终局发电路线，支持 NEI 展示。双流体制造配方仅注册到多方块搅拌机配方表，不加入单方块搅拌机。

方块与流体资料分别位于 `wiki/blocks/` 和 `wiki/fluids/`；具体实现、配置默认值与范围以源码及字段旁注释为准。

无线升级芯片为本模组独立物品，通过右键核电站／涡轮主机永久解锁，重复升级不消耗，升级随存档与主机掉落保留；当前未添加制造配方。升级后，无动力仓时将实际逐 tick 发电量存入主机所有者所属的 GT 无线电网／团队，安装普通、多安培或激光动力仓后仍走有线输出；供热模式不额外发电，热交换站不支持升级。材质由用户提供的 `dev/texture-workbench/wireless_upgrade_chip.png` 原字节同步到运行资源。

## 目录结构

```text
src/main/
├── java/com/lin/thermonuclear/  # 模组生命周期与配置
│   ├── api/                   # 燃料、冷却液与换热规则接口及注册表
│   ├── loader/                # 内容注册与加载
│   ├── block/                 # 方块基类、分级组件及配套 ItemBlock
│   ├── item/                  # 物品基类、增殖棒公共机制与路线变体
│   ├── machine/               # 机器逻辑、结构与专用仓口
│   ├── nuclear/               # 核燃料与冷却处理
│   ├── recipe/                # 换热、发电计算与展示配方
│   ├── registry/              # 统一物品引用、流体登记、冷却液及蒸汽类型定义
│   ├── gui/                   # 机器界面
│   ├── nei/                   # NEI 集成
│   ├── asm/                   # CorePlugin 入口
│   └── mixins/                # Mixin 加载入口
└── resources/                 # 加载配置、本地化与材质
dev/                           # 结构导出与材质开发工具
docs/                          # 开发知识与专题资料
plan/                          # 产品规划与任务
```

目录说明只覆盖主要职责，不维护逐文件清单；局部实现细节不写入知识库，仅在关键代码处注释。

方块与物品的公共基类负责 Forge 注册，分类类定义等级／变体，Loader 组织加载；原 `ModItems` 品牌提示登记已合入 `loader/ItemLoader`。`TNItemList` 统一列举机器、仓口、方块物品与普通物品，由各 Loader 绑定；`get(amount)` 返回保留元数据及 NBT 的独立副本，拒绝未绑定读取、重复绑定及无效物品，init 结束前检查全部条目已绑定。配方和 NEI 通过枚举取物品，结构判定仍使用有类型的方块入口及等级集合；枚举不执行注册、不分配机器 ID。轴向能力合入方块基类，分级组件由父类统一注册；各等级仍使用原注册名，方块元数据只存轴向，增殖棒 damage 只存进度，不合并为元数据物品。

方块公共基类统一通过 `canCreatureSpawn(...)` 返回 `false`，禁止燃料棒、涡轮轴和扇叶方块作为自然生成生物的承载面，覆盖全部等级与朝向；不限制附近实体出现或绕过该判定的生成方式。该入口与 GT5U `.133` 的 `BlockCasingsAbstract`、GTNL `common/block/casings/{base,column,casing}/` 对应基类一致。

方块分类类在构造器中用 `addInfo(语言键, 参数...)` 按顺序声明提示，语言键不绑定注册名；同类各等级共用说明只声明共享键，等级专属说明单独追加，多行逐键调用。`ItemBlock` 传递完整悬停上下文，基类在悬停时翻译并格式化；涡轮轴共用 `thermonuclear.tooltip.turbine_shaft.0`，燃料棒共用 `thermonuclear.tooltip.fuel_rod.0`，按等级传入热量和并行上限。燃料棒分类类统一提供等级参数，核电站与 Tooltip 共用，不在语言文件维护数值。

## 验证与知识维护

- 燃料棒结构等级决定热容量与最大并行；电源面板限制新批次装载。主子结构全部管道匹配主结构管道等级，全部燃料棒匹配主结构燃料棒等级，两维独立。管道仅控制模块总数上限，不控制燃料棒等级或批量。旧热容量与管道批量配置仅兼容保留，不再控制运行。
- 结构降级不丢弃已有燃料或热量；超出等级并行上限的批次暂停，冷却仍可排热。热量加载与事务回滚不按尚未恢复的结构等级截断。
- 安全壳机械方块已接入 GT 原生机器更新传导，放置／破坏会发起结构复查通知；材质引用和 StructureLib 结构匹配本身不提供此能力。通知沿可传导方块传播，不保证即时停机，游戏行为待验收。
- 扩展整轮结果提交后，开关开启或仍有预付周期时等级变化走原生停机，等待手动重启；保存等级仅用于比较，恢复前必须重验。扩展搜索随 GT 原生结构检查触发，不固定轮询、不随配方周期扫描；远端变动未触发原生通知时使用 GUI 手动检查。主结构缺区块暂停、恢复后复验，扩展缺区块在结构检查时按断连降级，不主动加载区块。扫描采用单调时钟超时，失败不提交部分等级。独立几何模型不证明游戏停机、存档或性能正确。
- 扩展组织参考 GTNL `PCBFactory` 的独立片段与多次 `buildPiece()`，不复用其固定布局或 `.183` API；按本地 GT5U `.133`／StructureLib `1.4.42` 核对 API。模块模板与几何合入 `NuclearModuleStructure`，真实匹配通过 `iterate()` 复用建造／预览的结构元素；先确定主等级，保留整盒区块预检、逐元素超时与显式失败记录，不使用会更新主结构统计的 `checkPiece()`。BR6343 通道枚举用于发现 `extra`，不新增编译依赖。
- `extra` 通道必须小写；客户端可选 BR6343 late Mixin 将核电站的滑条标题保留为 `extra`，避免与蓝图输入混淆，不改变其他机器标题。世界全息与自动搭建采用相同通道选择；生存蓝图对空右键可配置，未新增生存自动建造接口，游戏行为待验收。
- 管道升级参考 GTNL `LapotronChip` 的 `ofBlocksTiered()` 与 `Desulfurizer` 的管道外壳入口；按缓存 GT5U `.133`／StructureLib `1.4.42` 核对三种外壳、同级判定与 `pipe` 建造通道，不采用参考库 `.183` 的结构通道封装。
- 热量超限不立即停机，持续超限后先清空主结构 `G` 位置的水，再将主结构与本轮有效模块 `D` 位置现存燃料棒替换为岩浆并停机；模块草稿不新增结构水。融毁目标缺区块时不加载区块、不执行部分融毁；计时与原有 NBT 规则保留，游戏行为待验收。
- 冷却液对与核电吸热参数独立于换热规则，核电站不再依赖热交换配方；核电蒸馏水直冷仍产普通蒸汽。换热规则在工作流体解析后注册并冻结，一种冷却液仅绑定一种蒸汽，重复定义拒绝、缺失流体路径禁用，运行与 NEI 共用可用规则。水耗额度及按稳定蒸汽标识保存的余量继续保留；旧蒸汽模式忽略，普通蒸汽余量不转成过热蒸汽。重构尚未编译或游戏验收。
- 涡轮选汽在扣除流体前检查轴等级，运行 tick 同样复查；低压轴不消耗超超临界蒸汽，结构降级后不继续该蒸汽的预付发电。
- 公共基类通过 `FluidStack.isFluidEqual` 匹配输入及去重 ME 同种库存，遵循流体与 NBT 比较语义；指定仓口的统计与扣除共用 ME／多流体仓口遍历并保留原始事务栈。参考 GTNL `SteamMultiMachineBase#getStoredFluids()`，API 核对本项目缓存 GT5U `.133`，不采用参考库 `.183` 的新增接口；真实 AE 网络行为待游戏验收。
- 增殖池与专用物品仓口独立于普通燃料，输入扣除延迟到周期事务成功；NBT 快照包含增殖进度和待输出产物。
- 联机流体 ID 以服务器为准；换热与涡轮 NEI 预览通过 GT 显示 getter 隐藏不可用流体槽，保留槽位及实际配方，不使用 Mixin。服务器缺少本模组时预览可能不完整；共享工业搅拌机制造配方不在此防护范围，游戏行为待验收。
