## 项目定位与事实来源

这是为 GTNH 编写的热核与蒸汽能源扩展附属模组。项目目标来自[规划原稿](../../../GTNH-Thermonuclear-Expansion-Plan.md)，实现现状来自 `src/` 和根目录构建配置；这两种事实不得混用。

规划的核心方向是从 EV 阶段扩展 `IC2 热冷却液 -> 热交换 -> 蒸汽 -> 涡轮 -> 电力` 链路，改善蒸汽能源的吞吐量、效率和持续升级体验。规划第 3.2 节明确不建立温度数值、温度区间或温差计算。所有热交换、压力、流体与发电行为目前均未实现。

| Minecraft | `1.7.10`，`gradle.properties` |

| 模组名 / ID | `Thermonuclear` / `thermonuclear` |

| Java 语法模式 | `enableModernJavaSyntax = jabel`；现代语法与 Java 8 字节码目标分开处理 |
| Gradle Wrapper | `9.4.0`，`gradle/wrapper/gradle-wrapper.properties` |

`2.9.0-beta-3` 是当前构建清单值，不等同于已经完成该整合包的兼容性验收。GT5U 等具体模组版本通过清单解析，不能照抄来源文档中的 RC-1 或旧源码快照版本。

本次 `dependencyInsight` 实际选中 GT5U `5.09.54.133` 和 NewHorizonsCoreMod `2.9.61`；后者的传递 GT5U `5.09.54.129` 被冲突处理替换为 `.133`。版本敏感的 API 以最终选中的 JAR 为准。

## 已有文件与执行入口

| 文件（相对仓库根目录） | 职责与现状 |
| --- | --- |
| `src/main/java/com/lin/thermonuclear/Thermonuclear.java` | `@Mod` 入口；转发 preInit、init、postInit、serverStarting 到代理 |
| `src/main/java/com/lin/thermonuclear/CommonProxy.java` | preInit 读取配置并输出示例日志；其余阶段为空 |
| `src/main/java/com/lin/thermonuclear/ClientProxy.java` | 继承通用代理，尚无客户端渲染注册 |
| `src/main/java/com/lin/thermonuclear/Config.java` | Forge `Configuration`；只有 `general.greeting`，默认 `Hello World` |
| `src/main/resources/mcmod.info` | Gradle 替换元信息占位符；描述、URL、作者仍保留模板内容 |
| `build.gradle.kts` / `settings.gradle.kts` | 应用 Elytra 与 GTNH 构建插件，管理插件仓库 |
| `dependencies.gradle` / `repositories.gradle` | 模组依赖声明与附加 Maven 仓库 |
| `.github/workflows/` | 模板的构建、测试和标签发布工作流；不代表发布环境已验收 |

`Tags.VERSION` 由 `generateGradleTokenClass = com.lin.thermonuclear.Tags` 生成。`src/` 中不存在机器、配方、流体、语言文件、Mixin 实现或测试。`CommonProxy` 的 `MyMod` 日志也是模板残留，不能用它判断模组 ID。

## 外部依赖与迁入知识

用户指定的只读代码参考为 `D:\DEV\mcmod\GT-Not-Leisure`。编写或修改功能前先检索相关实现，再核验本项目 API 并实施；目录、机器与配方入口及版本差异见 [GTNL 参考索引](../references/GT-Not-Leisure参考索引.md)。这不构成对 GTNL 的构建依赖，也不代表其功能已经迁入。

`dependencies.gradle` 已迁入一组较大的整合包依赖，包括 GT5U、NewHorizonsCoreMod、IC2、NEI 和其他科技/魔法模组，也保留了对 `libs/spark.jar`、`libs/OmniOcularUnofficial.jar` 的支持；文件存在时才加入本地运行时依赖，本仓库没有这两个 JAR。依赖列表不代表代码已经集成这些模组。

[迁入资料使用说明](../references/迁入资料使用说明.md)规定了 MessTech 知识的使用边界。任何机器基类、注册流程、GUI 或库存算法，在成为本仓库实现前，都必须核验当前依赖并实际编写、验证。

## 规划中的未定事项

原稿存在以下内部冲突，本次知识初始化不替用户定案：

- 第 4.1 节规定唯一新增热交换设备为多方块热交换站；第 11.2、14.1、15 节仍出现增强型或两个新增等级热交换机。
- 第 1.2、2.1 节以 EV 为起点，但第 2.1 节另有“IV 之前不纳入首发”的描述。
- 原稿使用 JEI/NEI 混合表述；当前依赖声明为 NotEnoughItems，界面集成尚不存在。
- 蒸汽能量价值、机器结构、压力模型、维护机制和首发范围没有经过本项目代码或游戏验收。
- 原稿中的极热交换机数值属于规划记载，没有在当前解析的 GT5U JAR 中复核。

实现具体机器前确认对应范围、配方和数值。当前没有分配 Thermonuclear 机器 ID，也没有注册新流体。
