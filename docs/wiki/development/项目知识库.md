# Thermonuclear Expansion 项目知识库

> 最后更新: 2026-10-07

## 项目定位与当前实现

面向 GTNH 的热核与蒸汽能源扩展附属模组，规划从 EV 阶段扩展 `IC2 热冷却液 → 热交换 → 蒸汽 → 涡轮 → 电力` 链路，不建立温度数值或温差模型。[规划原稿](../../../GTNH-Thermonuclear-Expansion-Plan.md)描述目标，`src/` 与构建配置描述实现，两者分开使用。

三台原型已有独立结构、GUI、NBT 和双语资源，共享 20 tick 处理周期与 GT 送电链：

| 机器 / 批准 ID | 当前能力 |
| --- | --- |
| 核电站 / `32100` | 直接发电或供热；供热存入可配置、可存档的热缓存，由冷却液带走；8 级同级管道控制燃料批量 |
| 热交换站 / `32101` | 热冷却液与蒸馏水换热，返还冷却液，选择普通、过热或超临界蒸汽；当前结构 `9×14×7` |
| 大型蒸汽涡轮机 / `32102` | 使用 GT 转子消耗普通蒸汽发电并回收蒸馏水；当前结构 `3×3×3` |

机器 ID 从 `32100` 递增已获用户批准，注册时检查范围与占用，冲突即失败，不覆盖或自动改号。当前仅为创造模式测试内容；没有制造配方、主控电路板、温度／布局机制、维护故障、超超临界蒸汽、终局机器或最终平衡。

结构、燃料公式、运行事务、预览兼容与配置详见[原型开发指南](第一阶段原型开发指南.md)。燃料热值不等于 IC2 原版散热缓存或 GUI 热输出，区分依据见[IC2 燃料棒公式](../references/IC2-2.2.828反应堆燃料棒公式.md)。

## 已有文件与执行入口

下表 Java 路径相对 `src/main/java/com/lin/thermonuclear/`，资源及构建路径相对仓库根目录。

| 文件 / 目录 | 职责与现状 |

| `Thermonuclear.java` / `CommonProxy.java` | Forge 生命周期；preInit 读配置，init 注册燃料适配器与机器，loadComplete 解析流体；GT、IC2、StructureLib 前置 |
| `ClientProxy.java` / `Config.java` | 客户端代理尚无渲染注册；Forge 配置保留 `general.greeting` 与范围校验的 `prototype` 分类 |
| `loader/MachineLoader.java` | 注册三台控制器并保存物品引用 |
| `machine/` | 各主机持有结构、校验和建造入口；`ThermonuclearMultiblockBase` 共享周期、事务、启动、送电、NBT 与 Waila |
| `machine/NuclearPowerPlantStructure.java` | 展开[核电导出结构](../../../dev/nulcearStructure.txt)，`27×25×32` 旋转为 `32×25×27`，主机偏移 `(4,21,11)` |
| `gui/` | 公共终端布局与三台专属 GUI，按主机和模式同步字段 |

| `nuclear/` | GT 燃料适配、效率策略、最低寿命优先装载与批次数量存档；默认批量上限 `256×管道等级`，最高 2048 根 |
| `nuclear/NuclearCoolingMath.java` | 核电整数升冷却、热量保留、出口容量限流及蒸汽小数余量计算；供热模式允许无燃料时仅冷却，GUI 分别按实际输入和输出显示流量 |
| `registry/WorkingFluids.java` / `ModItems.java` | 复用已有流体，不注册新流体；按物品及准确元数据添加双语品牌 tooltip，搜索词 `thermonuclear` |
| `recipe/HeatExchangeRecipe.java` / `HeatExchangeSteam.java` | 两条冷热冷却液路径、三种蒸汽与可配置产出倍率 |
| `src/main/resources/assets/thermonuclear/lang/` | `zh_CN.lang`、`en_US.lang`；名称、模式、结构和状态提示 |
| `src/main/resources/mcmod.info` | Gradle 替换元信息占位符；描述、URL、作者仍保留模板内容 |
| `asm/ThermonuclearCorePlugin.java` / `mixins/LateMixinLoader.java` | early / late 加载入口，无 ASM 补丁或实际注入；JSON 位于 `src/main/resources/`，见 [Mixin 指南](Mixin开发指南.md) |
| `build.gradle.kts` / `settings.gradle.kts` / `dependencies.gradle` / `repositories.gradle` | 构建插件、清单依赖与 Maven 仓库 |
| `.github/workflows/` | 模板的构建、测试和标签发布工作流；不代表发布环境已验收 |

## 验证与知识维护

核电供热在开机且结构有效时先冷却已有热量，独立于燃料可用性；关机和直发模式不冷却。只转换已有热量足够加热的整数升冷却液，未转换热量留在缓存；出口不足时缩减批量。蒸馏水产汽余量使用 `tnDistilledSteamRemainder` 保存，旧存档缺失为零，不把旧的未参与运算的冷却液／水余量键迁移为蒸汽。满负荷流体速率按转换比例显示，实际蒸汽速率使用本批输出量。公式和事务边界见[原型开发指南](第一阶段原型开发指南.md#燃料适配与核电模式)，实际游戏及特殊仓室行为仍需验收。

用户要求后续不要执行 Gradle 脚本，开发代理在用户重新明确允许前不运行 Wrapper、系统 Gradle 或间接调用脚本。独立验证仅记录自身覆盖范围，未执行的编译、Spotless 和打包检查保持未验证。

已有格式化、编译、资源处理和部分源码检查记录，未完成本模组游戏显示、物料守恒、性能、真实仓室或整合包兼容验收。当前无 `src/test/` 或 JUnit 测试依赖；历史六项辅助测试与完整构建成功只适用于当时工作区，不代表当前验收。命令与检查范围见 [Gradle 指南](Gradle开发指南.md)，`help` / `tasks` 成功仅表示配置初始化完成。

功能变更后就地维护真实入口、配置、ID、依赖与验证边界，不将规划写成已实现。修订写入[文档修订记录](../../文档修订记录.md)，命令与结果写入[开发验证记录](../../开发验证记录.md)；历史记录及 `wiki/archive/` 仅按需追溯，统一规则见 [AGENTS.md](../../../AGENTS.md#文档维护与历史读取)。
