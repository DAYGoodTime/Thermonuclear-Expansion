# Thermonuclear Expansion 项目知识库

> 最后更新: 2026-10-06 18:23

## 项目定位与事实来源

这是为 GTNH 编写的热核与蒸汽能源扩展附属模组。项目目标来自[规划原稿](../../../GTNH-Thermonuclear-Expansion-Plan.md)，实现现状来自 `src/` 和根目录构建配置；这两种事实不得混用。

规划的核心方向是从 EV 阶段扩展 `IC2 热冷却液 -> 热交换 -> 蒸汽 -> 涡轮 -> 电力` 链路，改善蒸汽能源的吞吐量、效率和持续升级体验。规划第 3.2 节明确不建立温度数值、温度区间或温差计算。

第一阶段已编写核电站、热交换站、大型蒸汽涡轮机三个控制器及公共原型层，配套配置、GUI、NBT 和语言资源。核电站供热模式按 `nuclearHeatOutputMultiplier × 燃料理论热值` 将产热存入 `prototype.nuclearHeatCapacity` 配置的可存档缓存；燃料适配器直接根据工作 `ItemStack.stackSize` 判定反射规则，数量大于 4 时普通发电和供热均按最大反射脉冲计算每根燃料棒，供热倍率保持由当前配置决定。默认缓存上限 50000，冷却液从缓存带走热量并输出对应热流体；热交换站可选择普通、过热或超临界蒸汽，并按实际处理量产出；大型蒸汽涡轮机仍只处理普通蒸汽。IC2 原版燃料热量、`EmitHeatbuffer` 与流体 GUI 显示不是同一个量，源码核对和实测边界见[IC2 2.2.828 反应堆燃料棒公式](../references/IC2-2.2.828反应堆燃料棒公式.md)。验证范围仍不包含本模组完整游戏功能验收。制造配方、主控电路板、温度、布局、维护故障、超超临界蒸汽和终局机器仍不在当前实现中。实现细节与依赖核验见[第一阶段原型开发指南](第一阶段原型开发指南.md)。实现前的状态记载移入[历史归档](../archive/development/第一阶段前项目状态.md)。

## 外部依赖与迁入知识

核电站采用 [游戏导出结构](../../../dev/nulcearStructure.txt)：A 为 8 级同级物品管道外壳，D 为钢框架，F/H 为水源，G 为强化混凝土或物品总线／发电仓／可选维护仓，I 两处必须恰好一个流体输入仓和一个流体输出仓。G 不接流体仓或双输入仓。G/I 通过完整仓室元素提供 NEI 功能区高亮和支持方块查询；创造／NEI 构建的 I 默认使用一进一出的 ULV 仓，NEI 通过 `INEIPreviewModifier` 标记启用仅预览的放置回退，绕过上游仓室放置器对 `WorldServer` 假玩家的要求；实际校验不限等级并允许两个位置互换。`prototype.nuclearFuelRodsPerPipeTier` 默认 256、范围 1—256；管道等级是独立属性，目前只提高燃料批量，不改变单根燃料效率。热交换站与涡轮仍为 `3×3×3`。具体规则与验证边界见[原型开发指南](第一阶段原型开发指南.md#结构与仓室)。

用户指定的只读代码参考为 `D:\DEV\mcmod\GT-Not-Leisure`。编写或修改功能前先检索相关实现，再核验本项目 API 并实施；目录、机器与配方入口及版本差异见 [GTNL 参考索引](../references/GT-Not-Leisure参考索引.md)。这不构成对 GTNL 的构建依赖，也不代表其功能已经迁入。

`dependencies.gradle` 已迁入一组较大的整合包依赖，包括 GT5U、NewHorizonsCoreMod、IC2、NEI 和其他科技/魔法模组，也保留了对 `libs/spark.jar`、`libs/OmniOcularUnofficial.jar` 的支持；文件存在时才加入本地运行时依赖，本仓库没有这两个 JAR。依赖列表不代表代码已经集成这些模组。

[迁入资料使用说明](../references/迁入资料使用说明.md)规定了 MessTech 知识的使用边界。任何机器基类、注册流程、GUI 或库存算法，在成为本仓库实现前，都必须核验当前依赖并实际编写、验证。

## 规划中的未定事项

原稿存在以下内部冲突，本次知识初始化不替用户定案：

- 第 4.1 节规定唯一新增热交换设备为多方块热交换站；第 11.2、14.1、15 节仍出现增强型或两个新增等级热交换机。
- 第 1.2、2.1 节以 EV 为起点，但第 2.1 节另有“IV 之前不纳入首发”的描述。
- 原稿使用 JEI/NEI 混合表述；当前依赖声明为 NotEnoughItems，界面集成尚不存在。
- 蒸汽能量价值、机器结构、压力模型、维护机制和首发范围没有经过本项目代码或游戏验收。
- 原稿中的极热交换机数值属于规划记载，没有在当前解析的 GT5U JAR 中复核。

第一阶段范围以用户贴出的 OpenChamber 计划正文及后续确认内容为准；它与产品规划原稿分开记录，不修改原稿中的冲突。用户最终批准机器 ID 从 `32100` 开始递增，本阶段仅使用前三个。先前的 `45600` 提议超出当前 GT5U 注册表范围，未接入代码。原型数值集中配置，未确定最终平衡，也没有注册新流体；三种蒸汽均解析并复用整合包已有流体。

## 验证与知识维护

NEI 流体仓预览的直接放置必须携带有效的当前客户端玩家，让上游先初始化拥有者 UUID，再读取默认模式偏好；不传 null 玩家、不全局修改 GT 偏好查询。客户端玩家获取仅位于 `@SideOnly(Side.CLIENT)` 的预览回调，临时引用随构建结束清除。该路径不改变真实仓室校验或主机存档。

构建命令及其实际验证范围见 [Gradle 开发指南](Gradle开发指南.md)。Gradle `help` 或 `tasks` 成功只表示配置初始化完成，不等同于编译、打包或游戏测试成功。

添加功能后记录真实入口、配置项、注册 ID、依赖版本和验证结果。产品规划只有在功能实际实现后才进入“已有实现”章节。

已有 Wrapper 格式化、编译、资源处理及部分源码检查记录；未进行游戏显示、物料守恒、性能或真实仓室／整合包兼容验收。当前工作区无 `src/test/`，历史六项辅助逻辑测试通过不表示当前存在回归测试入口，也不证明游戏行为正确。历史完整构建成功、Spotless 阻断及其修复均只适用于对应时点。
