# Thermonuclear Expansion 项目知识库

## 项目定位与当前实现

面向 GTNH 的热核与蒸汽能源扩展附属模组，扩展 `IC2 热冷却液 → 热交换 → 蒸汽 → 涡轮 → 电力` 链路，不建立温度或温差模型。[规划原稿](../../../plan/GTNH-Thermonuclear-Expansion-Plan.md)描述目标，`src/` 与构建配置描述实现，两者分开使用。

当前机器能力：

| 机器 | 当前能力 |
| --- | --- |
| 核电站 | 消耗燃料直接发电或供热，直接发电支持芯片升级后的无线输出；支持分级热量缓存、并行设置、持续超限后的堆芯融毁与冷却排热；供热可加热钾钠合金复合冷却液，专用增殖总线支持 GT 锂棒／萤石棒及本模组稀土元素棒转换，完成棒经后续配方回收目标材料。 |
| 热交换站 | 根据输入热液自动选择唯一路径：IC2 热冷却液生产过热蒸汽，热超级冷却液生产超临界蒸汽，热钾钠合金复合冷却液生产超超临界蒸汽；消耗蒸馏水并返还冷却液，无蒸汽模式切换。 |
| 大型蒸汽涡轮机 | 消耗不同类型的蒸汽发电并回收蒸馏水，无需 GT 转子，支持设置耗汽上限及芯片升级后的无线输出；低压轴支持前三种蒸汽，高压轴额外支持超超临界蒸汽。 |
| 调试结构构建机 | 调试专用：只通过全息提示／蓝图自动搭建装载的草稿结构，骨架匹配即成型，不处理配方、不接受仓口；当前装载 `dev/nuc-child.txt` 草稿。 |

增殖为可选功能，专用输入／输出总线成对安装，不占普通燃料物品池或并行额度；增殖机制已完成，配方与机制当前事实以源码和本知识库为准，早期计划仅作归档保留。

核电站使用主结构背面、右侧双入口的贴墙模块扩展：主子结构保留独立模板与完整外墙，统一主机水平朝向，子模块通过四个水平相邻方向的 BFS 连通搜索识别。管道等级继续决定模块总数上限；模块管道与燃料棒分别只读匹配主结构对应等级，燃料棒另须竖直放置，不接受混级或借失败模块继续连接。完整模块才计数，达到上限立即停止；NEI `extra` 提供仅主结构、背面一片、背面连续两片三级示例，主子结构共用 `reactor_pipe`／`fuel_rod` 通道；世界全息与自动搭建采用同一示例选择，不限制实际自由连接。几何、模板与验收边界见[核电站模块结构](核电站模块结构.md)

核电站主结构与每个有效扩展模块各提供一个独立燃料批次，允许不同燃料与寿命同时运行，每批独立使用并行设置，发电与产热逐批求和；热容量、冷却能力和增殖池容量不随模块数扩大。乏燃料占用原批次槽直至输出，其他批次继续运行；降级超限保留燃料并暂停。燃料池统一支持逐批 NBT、旧单批存档迁移及事务回滚，游戏行为待验收，详见[核电站模块结构](核电站模块结构.md#运行融毁与存档边界)。

核电站成型并关机后，可用 GUI 弹出按钮将各批内部工作燃料棒送至普通输出总线；输出不足时保留剩余棒及各自进度，输出全堵时不改动物料。弹出棒的不足一个周期的已用寿命向上取整，寿命耗尽则输出乏燃料；不弹出增殖棒，不改变原有待输出产物流程。

**新增方块系列**

新增方块、流体和物品的设计草稿位于 `docs/draft/`，按类型分目录；定稿后冻结，后续功能完善与缺陷修复不再修改草稿。当前实际行为以源码、本知识库与开发验证记录为准。

- 低压／高压涡轮轴方块，用于涡轮结构，支持按放置方向调整轴向；等级限制蒸汽准入，超超临界蒸汽仅允许高压轴使用。涡轮轴与燃料棒方块均使用扳手采集，GT 扳手右键可调整轴向。
- 燃料棒方块，用于核电站结构等级决定核电热容量和最大并行；结构内只接受竖直放置（轴向元数据 0），横放或斜向不算有效方块。
- 燃料棒各等级热容量与最大并行由 `Config.nuclearPowerPlant` 的顺序数组配置，重启生效；GTNHLib `0.11.52` 不支持 `long[]`，热容量以字符串列表持久化并精确解析为 `long[]`，启动时校验等级数量与正数范围。
- 新增涡轮扇叶方块：引用钢块材质，用于涡轮结构。
- 新增安全壳机械方块：沿用 GT 强化混凝土材质，用于核电站主结构外壳、可替换仓口位置及扩展模块壳体。

**新增流体系列**

- 超超临界蒸汽；作为热交换机高级输出蒸汽，接入高压轴涡轮发电。
- 冷／热钾钠合金复合冷却液: 只能通过工业搅拌机制造，作用于热交换机和反应堆热模式的冷却液。

具体实现、配置默认值与范围以源码及字段旁注释为准。

**新增物品系列**

- 无线升级芯片: 右键本模组电力机器解锁 ”无线电网“模式，机器拆除后仍保留，当前未添加制造配方。在”无线电网“模式下，机器不需要安装动力仓\能源仓，能量输入输出直接从主机所有者所属的 GT 无线电网／团队中进行交互。如果安装了能源仓室，则继续按原来逻辑执行，不进入无线模式。

硅岩基燃料棒已有 Mk I—VI 六级工作／枯竭独立物品，使用 GT 硅岩棒纹理引用。`ItemNaquadahFuelRod` 通过内部 `Tier` 枚举维护等级参数与物品引用，按等级成对创建工作棒与枯竭棒，由 Loader 绑定至 `TNCItemList`。公共 `ItemFuelBase` 继承 `ItemRadioactiveCellIC`，集中处理显示、堆叠及热量封顶，并内聚继承 `ItemBase` 的普通枯竭物品；不再设置独立的硅岩枯竭棒类。寿命使用 GT 的 `advDmg`，NEI 由 GT 父类生成铀模型、中子脉冲、发热量与发电量四项说明。罐装机封装对应液体燃料并回收枯竭流体和空棒壳。核电站优先使用专用适配器保留整数热值与既有反射、增殖规则；原生 IC2 使用父类脉冲和耗尽机制，单次产热及堆芯热量封顶为 `int` 上限。保留既有工作棒／枯竭棒注册名及耐久格式，不提供更早版本的名称或耐久迁移。编译与游戏行为待验收。

核电站燃料基础产热、热缓存整数部分与容量使用 `long`，小数余量单独保存；产热汇总及冷却扣热不将整数缓存转成 `double`，缓存按 `long` 上限饱和。NBT、事务回滚、停机冷却和融毁比较使用同一热缓存；热容量数值不因类型扩展自动增大，流体单次传输量仍受原生 `int` 限制。

目录说明只覆盖主要职责，不维护逐文件清单；局部实现细节不写入知识库，仅在关键代码处注释。

生命周期、配置与代理入口仍位于根包；`CommonProxy` 组织 `common/loader/` 的加载，`api/TNCItemList` 继续作为统一物品引用入口。核电站结构协作位于 `common/machine/nuclear/`，燃料、增殖与热量处理位于 `common/nuclear/`，不再使用根包下旧的 `machine/`、`nuclear/`、`gui/` 或 `nei/` 路径。目录归类不等于物理侧隔离：当前 `common/recipe/` 仍包含 NEI 配方前端，不能据此宣称专用服务器加载已验收。

方块与物品的公共基类负责 Forge 注册，分类类定义等级／变体，Loader 组织加载；`TNCItemList` 仅保存统一物品模板、提供副本读取与物品比对，由各 Loader 绑定。`get(amount)` 保留元数据及 NBT，不限制为 64 个；允许重新绑定，无效绑定记录警告并保留原模板，未绑定读取仍报错，不再执行 init 全表绑定检查。`isStackEqual` 沿用 GT 统一化比较，可选择通配元数据与忽略 NBT。燃料等级与增殖路线各自维护工作棒／耗尽或完成棒的引用，ItemList 不依赖这些业务类型。配方和 NEI 通过枚举取物品，结构判定仍使用有类型的方块入口及等级集合；枚举不执行注册、不分配机器 ID。轴向能力合入方块基类，分级组件由父类统一注册；各等级仍使用原注册名，方块元数据只存轴向，增殖棒 damage 只存进度，不合并为元数据物品。

方块分类类在构造器中用 `addInfo(语言键, 参数...)` 按顺序声明提示，语言键不绑定注册名；同类各等级共用说明只声明共享键，等级专属说明单独追加，多行逐键调用。`ItemBlock` 传递完整悬停上下文，基类在悬停时翻译并格式化；燃料棒分类类统一提供等级参数，核电站与 Tooltip 共用，不在语言文件维护数值。

机器 GUI 在前部显示服务端有序 `displayInfo()` 快照中的专属信息，后接完整 GT 原生终端；周期进度及运行中的产量由原生组件显示，去重只发生在 GUI，不删减其他渠道的快照。专属信息在客户端本地化，不依赖客户端机器状态确定键集；停机冷却没有运行周期，保留自定义产量。诊断与产出组件仅创建一次，游戏内布局、滚动及速率仍待验收。

核电站与大型蒸汽涡轮的 Waila 发电行复用 GT 原生显示，取启动进度生效后、动力仓限流前的产电功率，不表示实际注入动力仓／无线网的电量；停机或零产电时不显示发电行，实际能量结算与无线升级提示不变。

有线发电以 `long` 电量逐仓直接写入动力仓缓存，受每仓额定功率和剩余容量限制，不调用 GT 原生发电分配方法；未接收电量直接丢弃，不统计弃电或累计小数余量。无线输出仍按运行 tick 直接计入 GT 电网。

周期机器的 GT 原生效率读数逐 tick 跟随预热进度，停机随预热衰减，结构失效后清零；无预热模式在运行时显示满效率。原生效率增量保持为零，实际发电仍只应用一次预热倍率，不使用效率读数再次折算。

## 验证与知识维护

- 三台生产主机通过 `TNCCycleMachineBase` 统一周期执行、预付运行与周期 NBT；`CycleContext` 持有本次输入引用、延迟扣料、成功提交及内部状态回滚，先准备、再扣输入、最后按 GT 原生结算结果提交产物，不提供跨仓口／AE 网络的全局原子回滚。核电扩展历史等级与本次验证状态分开保存，结构重检不清除等级变更比较历史；重载后仍须重验。参考入口见 [周期处理与事务边界](../references/GT-Not-Leisure参考索引.md#周期处理与事务边界)，编译与游戏行为待验收。
- 生产产物在事务成功后进入 GT 原生待输出缓存，完成周期时重新检查当前仓口并输出；换热站区分冷热输出，核电站区分普通与增殖总线。普通关闭完成本轮但不开下一轮，强制停机清除进度与待产物；完成时堵塞沿用原生丢弃语义，不另设等待缓存。重载恢复 GT 待产物及本模组路由、预付运行状态，不重新扣料；无运行周期的停机冷却在本次事务中直接输出。
- 扩展整轮结果提交后，开关开启或仍有预付周期时等级变化走原生停机，等待手动重启；保存等级仅用于比较，恢复前必须重验。扩展搜索随 GT 原生结构检查触发，不固定轮询、不随配方周期扫描；远端变动未触发原生通知时使用 GUI 手动检查。生产机器主结构统一交给 GT 原生 `checkPiece()`，不增加逐 tick 区块预检或独立高度预检；扩展缺区块在结构检查时按断连降级，不主动加载区块。扫描采用单调时钟超时，失败不提交部分等级。独立几何模型不证明游戏停机、存档或性能正确。
- 扩展组织按 GT5U 与 StructureLib 核对 API。模块模板与几何合入 `NuclearModuleStructure`，真实匹配通过 `iterate()` 复用建造／预览的结构元素；先确定主等级，保留整盒区块预检、逐元素超时与显式失败记录，不使用会更新主结构统计的 `checkPiece()`。BR6343 通道枚举用于发现 `extra`，不新增编译依赖。
- 投影仪的通道补全与说明只来自 StructureLib 全局注册表 `ChannelDescription`，不扫描机器结构：在 `CommonProxy.init` 中晚于方块注册调用 `StructureLibAPI.registerChannelDescription(通道, modid, 语言键)` 才出现在补全列表并带有说明 tooltip；再按等级调用 `registerChannelItem(通道, modid, 值, 物品栈)` 登记指示物，才支持从 NEI 拖入与中键拾取填入，该调用同时为物品追加指示物提示。语言键按 `channels.<modid>.<通道>` 写入 `lang`；通道名必须全小写，配置界面的输入框会强制转小写。未注册的通道仍可手动填写生效，BR6343 的 NEI 滑条不读此表。本模组通道集中在 `common/registry/StructureChannels`（`reactor_pipe`／`fuel_rod`／`turbine_shaft`／`extra`），等级方块按等级登记指示物；核电站管道不复用 GT 的 `pipe`，避免与 GT 以青铜起算的同名通道及相同外壳物品冲突。
- 公共基类通过 `FluidStack.isFluidEqual` 匹配输入及去重 ME 同种库存，遵循流体与 NBT 比较语义；指定仓口的统计与扣除共用 ME／多流体仓口遍历并保留原始事务栈，API 按当前 GT5U `.205` 核对，不采用参考库新增接口；真实 AE 网络行为待游戏验收。
- 联机流体 ID 以服务器为准；换热与涡轮 NEI 预览通过 GT 显示 getter 隐藏不可用流体槽，保留槽位及实际配方，不使用 Mixin。服务器缺少本模组时预览可能不完整；共享工业搅拌机制造配方不在此防护范围。
