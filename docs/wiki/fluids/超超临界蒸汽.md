# 超超临界蒸汽

> 最后更新: 2026-10-07

## 当前实现

| 项目 | 值 |
| --- | --- |
| 中文名称 | 超超临界蒸汽 |
| 英文名称 | Ultra-Supercritical Steam |
| 用户确认的注册名 | `thermonuclear.ultrasupercriticalsteam` |
| 本地化键 | `fluid.thermonuclear.ultrasupercriticalsteam` |
| 注册入口 | `registry/ModFluids.java`，由 `CommonProxy.preInit()` 调用 |
| 工作流体引用 | `WorkingFluids.ultraSupercriticalSteam`，在 loadComplete 解析 |

使用 Forge `Fluid` 注册，标记为气体；同名流体已被占用时明确失败，不覆盖或自动改名。流体数字 ID 由 Forge 分配，不占用 GT 机器 ID。

客户端运行时复用已注册的 GT `supercriticalsteam` 静态／流动图标；每次读取当前图标，因此兼容纹理重载，不复制外部纹理。上游流动图标缺失时使用静态图标，静态图标缺失时回退到 Forge 水图标。当前没有专用纹理、流体方块或容器物品。

## 接入与数值边界

热交换站提供普通、过热、超临界、超超临界四种输出。关闭主机且未运行时，使用 GUI 的蒸汽切换按钮循环选择；超超临界蒸汽排至 F 输出仓，B 输出仓完整返还对应冷却液。IC2 热冷却液、热超级冷却液两条路径均可配合蒸馏水生产该蒸汽，沿用输入库存及两侧出口容量限流机制。

`prototype.ultraSupercriticalSteamLitresPerHotCoolant` 独立控制产出倍率，原型默认 160 L 蒸汽/1 L 实际消耗热冷却液，范围 0.001—1000000。四种蒸汽的小数余量独立存档；新余量键为 `tnExchangeSteamRemainder_ultrasupercritical`，旧存档缺失时为零，原三种蒸汽的标识和余量键保持兼容。

大型蒸汽涡轮机仍只处理普通蒸汽，尚无超超临界蒸汽发电设备。

只设置气体标记，其余 Forge 物性保留默认值；默认物性及产出倍率均不代表已确认的温度、压力、热量或最终平衡。最终产出比例、EU/L 和设备门槛需另行确定，规划中的数值不作为已实现事实。
