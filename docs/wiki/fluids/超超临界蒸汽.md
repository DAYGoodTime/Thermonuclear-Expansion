# 超超临界蒸汽

## 当前实现

| 项目 | 值 |
| --- | --- |
| 中文名称 | 超超临界蒸汽 |
| 英文名称 | Ultra-Supercritical Steam |
| 用户确认的注册名 | `thermonuclear.ultrasupercriticalsteam` |
| 本地化键 | `fluid.thermonuclear.ultrasupercriticalsteam` |
| 注册入口 | `registry/ModFluids.java`，由 `CommonProxy.preInit()` 调用 |
| 工作流体引用 | `WorkingFluids.ultraSupercriticalSteam`，在 loadComplete 解析 |
| NEI 列表入口 | 客户端 `nei/NEIThermonuclearConfig.loadConfig()`，使用 GT 流体显示堆栈 |

使用独立 Forge `Fluid` 实例注册，标记为气体，并显式设置独立本地化名；它不是 GT 超临界蒸汽的别名。同名流体已被占用时明确失败，不覆盖或自动改名。流体数字 ID 由 Forge 分配，不占用 GT 机器 ID。

客户端运行时复用已注册的 GT `supercriticalsteam` 静态／流动图标；每次读取当前图标，因此兼容纹理重载，不复制外部纹理。上游流动图标缺失时使用静态图标，静态图标缺失时回退到 Forge 水图标。当前没有专用纹理、流体方块或容器物品。

NEI 按 `NEI…Config` 命名发现客户端插件，`GTUtility.getFluidDisplayStack()` 使用该独立流体的 Forge ID、名称、气体状态和图标创建显示堆栈，`API.addItemListEntry()` 添加条目。使用中文“超超临界蒸汽”或英文名称查询，U 用途可进入涡轮发电比例页。GT 默认流体列表仅在调试模式枚举，插件保留其默认条目再追加本流体，不依赖调试开关、不替换已有 NEI override。当前无生产路径，因此没有该流体的热交换产出配方；NEI 列表条目不代表实体容器。

## 接入与数值边界

IC2 热冷却液与热超级冷却液均禁止生成超超临界蒸汽。热交换站 GUI 仅循环普通、过热、超临界三种受支持模式；当前没有超超临界蒸汽生产路径。

流体注册、双语名称、工作流体引用和旧 `ultrasupercritical` 类型标识继续保留。旧存档选中此模式时，处理入口以 `steam_unsupported` 拒绝运行，不消耗输入或水耗额度；停机后切换可回到普通模式。旧超超临界蒸汽小数余量只保存，不参与产汽。旧配置 `prototype.ultraSupercriticalSteamLitresPerHotCoolant` 不再读取或生成，不能重新启用产出。

大型蒸汽涡轮机支持消耗超超临界蒸汽，无需 GT 转子，基础能量为 **10.5 EU/L**，实际发电仅乘启动倍率。独立 NEI 展示输入 1000 L、无输出槽、总能量 10500 EU；实际冷凝仍每 160 L 回收 1 L 蒸馏水。流体消耗与展示共用 `SteamTurbineFuel`。

只设置气体标记，其余 Forge 物性保留默认值；默认物性不代表已确认的温度、压力或热量。生产介质、产出比例和设备门槛仍未确定；当前 EU/L 使用用户指定值，不沿用规划中的其他数值。

## API 与验证边界

已核对本地 Forge `1.7.10-10.13.4.1614` 的 `Fluid`、`FluidRegistry`，GT5U `.133` 的 `GTUtility`、`ItemFluidDisplay`、`FluidDisplayStackRenderer` 以及缓存 NEI API 的插件命名和列表 override 语义。GTNL 只读参考为 `loader/BlockLoader.java` 的独立流体注册和 `client/nei/NEIGTNLConfig.java` 的 NEI 插件入口；参考库 GT5U `.183` 不作为本项目 API 基线，未复制其资源或调用 GTNL API。

Java 编译与格式检查通过；真实 NEI 插件加载、搜索、图标／纹理重载、流体传输、专用服务器加载仍待游戏验证。具体检查结果记录到[开发验证记录](../../开发验证记录.md)，整体入口见[项目知识库](../development/项目知识库.md)。
