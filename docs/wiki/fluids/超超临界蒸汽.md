# 超超临界蒸汽

> 最后更新: 2026-10-08 12:45

## 当前实现

| 项目 | 值 |
| --- | --- |
| 中文名称 | 超超临界蒸汽 |
| 英文名称 | Ultra-Supercritical Steam |
| 用户确认的注册名 | `thermonuclear.ultrasupercriticalsteam` |
| 本地化键 | `fluid.thermonuclear.ultrasupercriticalsteam` |
| 注册入口 | `registry/ModFluids.java`，由 `CommonProxy.preInit()` 调用 |
| 工作流体引用 | `WorkingFluids.ultraSupercriticalSteam`，在 loadComplete 解析 |

使用 Forge `Fluid` 注册，标记为气体；同名流体已被占用时明确失败，不覆盖或自动改名。流体数字 ID 由 Forge 分配，不占用 GT 机器 ID。

客户端运行时复用已注册的 GT `supercriticalsteam` 静态／流动图标；每次读取当前图标，因此兼容纹理重载，不复制外部纹理。上游流动图标缺失时使用静态图标，静态图标缺失时回退到 Forge 水图标。当前没有专用纹理、流体方块或容器物品。

## 接入与数值边界

IC2 热冷却液与热超级冷却液均禁止生成超超临界蒸汽。热交换站 GUI 仅循环普通、过热、超临界三种受支持模式；当前没有超超临界蒸汽生产路径。

流体注册、双语名称、工作流体引用和旧 `ultrasupercritical` 类型标识继续保留。旧存档选中此模式时，处理入口以 `steam_unsupported` 拒绝运行，不消耗输入或水耗额度；停机后切换可回到普通模式。旧超超临界蒸汽小数余量只保存，不参与产汽。旧配置 `prototype.ultraSupercriticalSteamLitresPerHotCoolant` 不再读取或生成，不能重新启用产出。实现入口与存档处理见[原型开发指南](../development/第一阶段原型开发指南.md#热交换与蒸汽涡轮)。

大型蒸汽涡轮机支持消耗超超临界蒸汽，基础能量为 **10.5 EU/L**，实际发电仍乘转子效率和启动倍率。独立 NEI 展示输入 1000 L、无输出槽、总能量 10500 EU；实际冷凝仍每 160 L 回收 1 L 蒸馏水。流体消耗与展示共用 `SteamTurbineFuel`，见[原型开发指南](../development/第一阶段原型开发指南.md#热交换与蒸汽涡轮)。

只设置气体标记，其余 Forge 物性保留默认值；默认物性不代表已确认的温度、压力或热量。生产介质、产出比例和设备门槛仍未确定；当前 EU/L 使用用户指定值，不沿用规划中的其他数值。
